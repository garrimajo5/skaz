## Назначение и предел

`SKAZ_PROFILE_EDITORS=0` отключает вход в UI-редакторы характеристик и класса. На странице героя есть объяснение. Чтение сохранённых ручных значений, история, игра, расход/отмена и экспорт продолжают работать в рамках прежних прав. Backend намеренно принимает разрешённые записи и точные повторы: уже отправленная команда должна завершаться после смены интерфейса. Флаг не является авторизацией или запретом пользовательского отклонения от правил. Значение по умолчанию1, принимаются только строки0/1; ошибочное значение отклоняется до открытия базы.

Это совместимая baseline, которую необходимо сначала принять и выпустить отдельно с выключенными редакторами. После её production-проверки второй шаг может включить редакторы, сохраняя эту baseline как ограниченный резерв для их UI-сбоев. Тот же backend не обеспечивает откат произвольной ошибки backend, общей загрузки JS или миграции. Старый4e407f0 новые профили не читает; возвращать его после новых данных нельзя. Вкладка получает новый флаг после загрузки HTML. Рабочую базу не подменять предрелизным резервом.

## Упаковка

```sh
node scripts/package-profile-recovery.mjs <полный-SHA-коммита> <новый-каталог-вне-checkout>
```

Упаковщик использует только указанное Git-дерево, не читает runtime environment или кампании. Он отказывает для mutable refs, старого кода без поддержки, существующего каталога, вывода внутри checkout и перечисленных приватных типов файлов. Имена Git читаются с NUL-разделителями, включая нелатинские имена. Фильтр расширений не доказывает отсутствие секретов внутри произвольно названного tracked-файла; проверка состава Git остаётся обязательной.

`candidate.json` фиксирует SHA, единственный дополнительный флаг и требование сохранить прежнюю авторизацию/остальные флаги. Его compatibilityVerified/releaseApproved остаютсяfalse: упаковщик не самоподписывает проверки. Отдельный verification.json связывает фактические проверки с тем же SHA. При несовпадении SHA использовать артефакт нельзя. Архивирование не включает untracked-файлы. Приватные базы/пароли/ключи/аудио в артефакт не переносились.

## Рефлексия и решение планировщика

Релиз-инженер: вместо абстрактного требования подготовлен конкретный архив и ограниченный режим восстановления с проверенной совместимостью. Лишняя работа — неверный запуск управляемого стенда безTTY. Предложение: локальный контроль стенда проверять до создания pending-операции. Польза — исключить лишний повтор; затраты — один тест управляющего переключения; риск — не подменить процессный restart сменой обработчика.

Планировщик: принять локальную проверку управления для этого сценария; общие инструкции не менять. Baseline считать проверенным кандидатом для ограниченного сценария, operationalrollback/Released не принимать до перечисленных проверок. Установка на production и принятиеM1 остаются отдельными действиями.
