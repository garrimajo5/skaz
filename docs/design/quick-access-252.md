# Быстрый доступ по Figma · #252

Рабочий экран открывается по `#play`. Первый этап [задачи #252](https://github.com/garrimajo5/skaz/issues/252) переносит компоновку [узла 3:3](https://www.figma.com/design/hskYV8FnfqELPW99dVMHXw/Skaz?node-id=3-3): навигация слева, герой и его состояние сверху, действия с видимой ценой в центре, ресурсы и хиты справа. На компактном экране остаются нижняя навигация и пульт, состояние героя расположено перед действиями.

На экране доступны существующие действия с заклинаниями и расходниками. Фильтры боя и исследования сохранены, можно отдельно выбрать действие, бонусное действие или реакцию. Из панели ресурсов открывается существующая история с доступной отменой. Меню кампаний, поиск правил, ручные счётчики, проверки и состояния героя продолжают работать через свои текущие входы. Последующие этапы #252 определяют закладки, поддерживаемые действия и перенос общей компоновки на остальные маршруты.

## Устройство кода

- `client/play-presentation.js` принимает типизированные данные экрана и форматирует их. Цена заклинания использует выбранный существующим контролом круг. Заговор помечен «Без ячейки», для пользовательского счётчика видна необходимость его выбора. Сводки используют прежний `SkazSpellFacts.summary`.
- `client/play.js` хранит фильтр, доступный круг и контекст загрузки. При обновлении возвращает клавиатурный фокус к тому же действию. Когда расход исчерпан, фокус возвращается к чтению соответствующей карточки.
- `client/app.js` переносит единственный пульт между игровым экраном и обычной оболочкой. Хиты, ячейки, очередь, права, концентрация и отмена продолжают использовать существующие команды `SkazStorage`. `client/play-layout.css` задаёт компоновку и использует токены трёх тем.

Для этого этапа достаточно JS и JSDoc. `npm run check:play` проверяет модуль представления без генерации JS. Во временной копии компилятор обнаружил строковый круг вместо числа (TS2345). Контракты большой оболочки и приложения остались за пределами `jsconfig.play.json`. Замена контроллера целиком увеличила бы число проверок прав, повтора, отмены и смены контекста в первом PR.

**ORM.** Этот этап использует прежние команды, HTTP-контракты, Node.js и SQLite через `node:sqlite`. Транзакция расхода, история и безопасный повтор уже покрыты регрессией. Для UI дополнительный слой данных не устраняет ни одного преобразования. Если в будущей задаче появится повтор SQL или расхождение типов в сохранении, сравнить текущий запрос, типизированную обёртку и ORM на одной транзакции с восстановлением. Схема и формат переноса здесь прежние.

## Воспроизведение

Запустить `node scripts/quick-access-fixture.mjs` и открыть `http://127.0.0.1:4337/#play` в одной тестовой вкладке. Каждый запуск создаёт отдельную вымышленную кампанию в памяти, с 11 заклинаниями и двумя зельями. В «Быстром доступе» сотворить «Волшебную стрелу» ячейкой первого круга и дождаться сохранения. В «Истории и отмене» отменить эту запись. Ожидаемый остаток ячеек 3 → 2 → 3.

Для сценария потери ответа запустить стенд с `--lose-cast-response`. Флаг срабатывает на первом успешном сотворении. Остальные команды подтверждаются штатно. Дождаться сообщения об ожидающем запросе и перезагрузить вкладку. Ожидаются одна запись расхода и остаток 2/4. Автоматическая проверка стенда — `node --test tests/quick-access-fixture.test.mjs`.
