# Карточки заклинаний: круг, компоненты и личные отметки — 18.11.2026

Refs #34. Frontend по прямому приоритету владельца, ветка frontend/spell-card-details.

## Изменение

Круг/заговор вынесен в отдельную метку, школа сохранена рядом с названием. V/S/M расшифрованы текстом; при M показан переход к описанию/источнику за материалами, стоимостью и расходом. Схема этих условий пока не содержит: цены, наличие предмета и расходование не угадываются.

Личные метки соответствуют модели героя: Известно / Изучено / В книге / Подготовлено / Постоянно подготовлено. Отсутствие записи не обозначается как запрет сотворения. Это отображение существующего состояния, не новая команда и не проверка легальности выбора.

Поиск показывает справочные результаты до ответа личной книги. Ошибка книги оставляет карточки доступными и объясняет отсутствие личных отметок. Ответ проверяется по текущему запросу, пользователю, герою и ревизии. Подробная карточка переиспользует только ещё выполняющийся запрос той же области; завершённые результаты не остаются отдельным долговременным кэшем.

Позднее обновление сохраняет клавиатурный фокус. При открытом диалоге обновление списка откладывается до его закрытия, чтобы не отсоединить элемент, куда браузер возвращает фокус.

## Передача

Независимые QA/геймдизайн, Android и выпуск остаются впереди; #34 и этап не закрываются. Следующий шаг контента: отдельные проверенные поля материальных условий с источником, затем отображение цены/расхода. Не извлекать их эвристикой из текста и не запрещать действие при отсутствии компонента.

Рефлексия: общий запрос книги уменьшает дублирование, но обновление фонового списка может отсоединить opener диалога. Поэтому тест теперь моделирует настоящий открытый/закрытый диалог. Предложение планировщику — включать поздний ответ фоновых данных при открытом диалоге в критерии подобных UI-задач; малая стоимость, предотвращает потерю фокуса. Общий процесс этим PR не меняется.
