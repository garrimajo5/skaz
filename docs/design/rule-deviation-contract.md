# Игровые отклонения: контракт для #78 → #85

18.11.2026. Предложение геймдизайнера на основании прямого решения владельца17.11
и PR107. Runtime не изменён; это вход для постановки, не независимая приёмка.
Личные данные и фактический состав героя здесь отсутствуют.

## Три независимых слоя

1. Обычный расчёт2014: справочное значение, источник и условия. Он объясняет
   предупреждение, но не запрещает игроку другой результат.
2. Выбранное состояние/действие: введённые значения и явные последствия. Может
   отклоняться от правила без обязательного флага мастера. Неполные данные не
   заполняются молча; ручной путь объясняет, что останется неизвестным.
3. Техническая команда: права на героя, валидный контекст, версия, повтор,
   безопасный формат и целостность. Исключение игрового правила этот слой не отключает.

## Жизненный цикл предупреждения

Минимальное описание для разработки: код правила и версия источника, целевой
герой и источник механики, фактическое/обычное значения, условие применимости,
текст объяснения. Для согласования — отдельная необязательная пометка и заметка.
Это требования к данным, а не утверждённый JSON/API-контракт.

Состояния: нет отклонения; отклонение без пометки; согласовано для этого условия;
условие изменилось и требует новой оценки; правило/значение неизвестно.
Неизвестность не выдаётся за нарушение. Удаление пометки не удаляет заклинание,
предмет или ручное число. Согласование другого источника или другого героя не
наследуется. При экспорте своего героя пометка и происхождение переносятся.

Обычные сохранения не требуют отдельного окна подтверждения для каждого
предупреждения. Подтверждение составного действия требуется там, где уже нужно
выбрать последствия (например, заменить концентрацию); игровые предупреждения
включаются в тот же обзор, не создавая цепочку дополнительных окон.

Если максимум изменился, нельзя обрезать текущий запас молча. Показывать сохранённое
значение, обычный максимум и предупреждение, дать отдельный выбор коррекции.
Технический предел хранения не равен игровому максимуму: он документируется
отдельно и не маскируется сообщением «по правилам нельзя».
