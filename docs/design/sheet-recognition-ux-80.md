# Заполнение профиля по листу — UX-спецификация

Issue [#80](https://github.com/garrimajo5/skaz/issues/80). Роль UX-дизайнер,16.11.2026. **Review: предложенный контракт взаимодействия**, не реализованный OCR и не согласование backend/геймдизайнера. [Цель](../PROJECT_GOAL.md), [ограничения](../governance/CONSTRAINTS.md), [визуальные правила](visual-guidelines.md).

## 1. Пользовательский результат

Игрок получает профиль по своему листу, видит что прочитано и что требует сверки, исправляет значения и подтверждает создание. Непонятное не превращается в выдуманное. Распознавание помогает заполнить поля, но не доказывает законность персонажа по правилам и не выбирает за игрока классовые решения.

## 2. Предлагаемый входной объём

Для первого этапа: печатный/заполненный машинным текстом лист2014 на русском или английском, PDF без пароля (текстовый или скан), PNG/JPEG страницы. Несколько страниц образуют один импорт; порядок можно исправить до анализа. Рукописные участки не обещаются к автоматическому чтению: выделяются для ручной сверки. HTML, архивы, ссылки на облачные аккаунты, исполняемые форматы и листы2024 не поддерживать первым этапом.

Это предложение UX для согласования с backend/геймдизайнером. Пример технических границ для оценки: до6страниц, до10MiB на весь импорт, до12мегапикселей декодированного изображения на страницу. **Не действующие лимиты API**: backend должен подтвердить или предложить другие до Ready #84. Текущие серверные лимиты и Nginx не меняются этим документом. Результат превышения лимита объясняет размер/страницу и даёт заменить файл без потери других страниц.

Приоритет MVP: создание нового профиля. Обновление существующего профиля по повторному листу требует отдельного контракта разностей; в первом потоке не перезаписывать его по имени. Уже существующий JSON-перенос остаётся отдельным действием «Импорт прогресса».

## 3. Поток и состояния экранов

1. **Выбрать лист.** Объяснение поддерживаемых форматов, кнопка выбора, информация об обработке и удалении до отправки. Никаких автоматически выбранных личных файлов.
2. **Проверить страницы.** Миниатюры, порядок, поворот/замена/удаление страницы. Файл с паролем/повреждением останавливает соответствующую страницу, не выдаёт пустые поля за результат.
3. **Прочитать.** Явный прогресс, отмена. Повтор сетевого запроса сохраняет ID задания. Ошибка сети предлагает повтор, не создаёт ещё одно распознавание. При отсутствии движка объяснить это, а не показывать фиктивные результаты.
4. **Сверить профиль.** Группы: личность/классы, характеристики/владения, здоровье/ресурсы, умения/заклинания, инвентарь. Счётчик «Нужно сверить N полей», фильтр проблем. Для каждого поля исходное изображение/фрагмент страницы, считанное значение, состояние и ручное исправление.
5. **Подтвердить создание.** Сводка классов, важнейших чисел и пропусков; выбранная кампания и действие «Создать нового персонажа» названы явно. Объяснить, какие неподдержанные механики требуют ручного управления. Без этого шага профиль не меняется.
6. **Результат.** Ссылка в профиль, список оставшихся необязательных полей и происхождение импорта. Повтор подтверждения открывает тот же созданный профиль. Никаких автоматических трат/отдыха/повышения уровня при импорте.

### Альбомный планшет1180×820

Две колонки: слева исходная страница с увеличением, справа текущая группа полей. Выбранное поле подсвечивает фрагмент источника. Сверху название этапа и число проблем; снизу явные «Назад» и «Далее». Фиксация панели действий резервирует место и не перекрывает поля.

### Портретный планшет820×1180

Группы и поля основным потоком, источник открывается рядом с выбранным полем либо в раскрываемой области. Нельзя уменьшать страницу целиком до нечитаемой миниатюры ради двух колонок.

### Телефон390×844

Одна группа за раз. Строка: название → исходное/распознанное → статус → поле исправления. Кнопка «Показать источник» открывает увеличенный фрагмент, закрытие возвращает фокус и прокрутку. Кнопка подтверждения доступна при клавиатуре; длинные списки не требуют горизонтальной прокрутки.

### Пример полей сверки

| Поле | Источник | Распознано | Состояние/действие |
| --- | --- | --- | --- |
| Ловкость | Стр.1, видно13или18 | Не определено | Выбрать/ввести значение; модификатор не решает автоматически |
| Текущие хиты | Пустое поле | Не указано | Уточнить; не копировать максимум |
| Заряды жезла | 0/7 | 0из7 | Ноль сохранён, можно исправить |
| Классы | Волшебник3 / Колдун2 | Две строки, общий5 | Сверить уровни и раздельные источники ресурсов |

Не показывать выдуманный процент уверенности. Если движок предоставляет калиброванную оценку, backend описывает её смысл; UX по умолчанию использует «Прочитано», «Нужно сверить», «Не указано», «Исправлено вами» с текстом и знаком, не только цветом. Все критические поля подтверждаются группой; высокая оценка OCR не разрешает пропуск подтверждения.

## 4. Модель полей и мультикласс

Не смешивать исходный текст, распознанный кандидат, ручное исправление и вычисляемое значение. Для переноса нужен источник страницы/области и происхождение, но не обязательно хранить весь личный файл бессрочно.

Классы — строки с именем/ID2014, уровнем и подклассом при наличии. Общий уровень сверяется с суммой; расхождение вызывает предупреждение с обоими значениями. Игрок может исправить данные либо сохранить явно выбранное ручное значение; подтверждение группы не блокируется игровым отклонением. Класс не выводится по списку заклинаний. Spellcasting и Pact Magic распознаются отдельными ресурсами, не складываются в одну таблицу. Известные/подготовленные/книга сохраняют источник; если лист не указывает его — предложить выбор либо явно сохранить неизвестное происхождение без автоматического назначения.

Печатный итоговый бонус не доказывает владение/компетентность. Если вычисленный результат отличается от листа, показать оба значения и источник ручного бонуса; не менять характеристики, чтобы добиться совпадения. Максимум хитов и текущие хиты отдельны; пустое значение отлично от0. Импортированный уровень не является повышением с1уровня и не выдаёт ресурсы/умения повторно.

Заклинание/предмет сопоставлять по точному подтверждённому ID/алиасу2014. Неизвестную строку оставить как несопоставленный фрагмент для сверки, не добавлять хомбрю в общий каталог. Только отсутствующие технически обязательные поля блокируют создание; неизвестные игровые сведения можно явно оставить для ручного уточнения без выдуманных значений. Окончательный список обязательных полей задаёт контракт #81/#82, а не UX догадка.

## 5. Ошибки, подтверждение и безопасность

- Лист другой редакции: остановить применение, объяснить поддержку2014, сохранить возможность вернуться к выбору файла.
- Противоречащие страницы: показать оба фрагмента и попросить выбрать; последняя страница не выигрывает автоматически.
- Потеря ответа при создании: сверить по прежнему ключу; не создавать дубль и не предлагать повторный новый импорт как первый выход.
- Конфликт/смена кампании: сохранить сверенные поля локального черновика в пределах прав, потребовать заново подтвердить назначение; не отправлять в новую кампанию молча.
- Выход с правками: «Остаться» / «Отбросить черновик». Восстановление черновика не отправляет форму автоматически.
- Удаление файла из предварительного набора не удаляет существующего героя. Отмена OCR не означает отмену уже подтверждённого создания; статус должен это различать.

До отправки объяснить, где обрабатывается файл и сколько хранится. Предложение: временное приватное хранилище, удаление исходника после подтверждения/отмены или по ограниченному TTL, отсутствие содержимого в журналах. TTL, пределы памяти/декодирования и поведение при сбое согласует backend. Не обещать локальную обработку, пока выбранный движок неизвестен. Внешние/платные AI API отдельно не разрешены.

## 6. Проверочный корпус и приёмка

[10 синтетических случаев](fixtures/sheet-review-cases.json) содержат отдельные исходные фрагменты и ожидаемые значения: одиночный класс, мультикласс с Pact Magic, неизвестные хиты, неоднозначное число, противоречие страниц, неизвестное заклинание, отметки владения, ноль зарядов, совпадающее имя и редакция2024.

Это **семантические fixtures для проектирования**, не изображения реальных листов и не доказательство точности OCR. Для Ready #84 нужен обезличенный визуальный корпус: каждый применимый случай в печатномPDF/PNG/JPEG, минимум один скан, один повёрнутый снимок, один с недостаточным качеством. Ожидаемые значения сверяются человеком независимо движка. Конкретные форматы/лимиты и визуальные исходники пока требуют backend/геймдизайнерского согласования; issue#80 не закрывается.

QA для будущей реализации: по каждому случаю сравнить поле, его неопределённость, источник и действие подтверждения; плохой результат допустим только как явно требующая сверки неопределённость, не как уверенное неверное число. Отдельно проверить3темы, клавиатуру/касания, обе ориентации, отсутствие потери текста и дубля после повтора. Точные пороги качества OCR устанавливаются по репрезентативному корпусу, не выдумываются в UX.

## 7. Передача и границы готовности

#84 backend: выбрать допустимый движок и временное хранение, подтвердить форматы/лимиты, source-region/поля/состояния, idempotency, блокирующие ошибки и назначение новой записи. #97 frontend: шаги, сравнение исходника, исправление, фокус/черновик, финальный предпросмотр. Геймдизайнер: проверить, что распознавание не скрывает отклонение от правил и сохраняет доступный ручной путь и что мультикласс виден игроку.

Эти заключения ожидаются; UX не принимает работу за другие роли. Приложение/сервер/микрофон не изменены. Выпуск приложения неприменим к документальной спецификации.

## Рефлексия

Результат: последовательный поток и10случаев, исключающих опасные догадки при заполнении. Ограничение: без подтверждённого движка/форматов нельзя честно обещать точность или завершение корпуса. Предложение планировщику — для распознавания разделить смысловую правильность, качество OCR и безопасное применение на разные критерии. Польза: ошибка чтения не скрывается за успешным сохранением; стоимость — отдельная матрица и корпус, риск — дополнительное время на подготовку.

## Уточнение при ревью 18.11.2026

Отклонения от правил2014 — предупреждения, а не запреты импорта или сохранения. Отметка мастера необязательна. Конфликт чтения исходных страниц требует выбора сохраняемого значения, но не обязательного выбора стандартного значения правил. Неизвестные происхождения остаются явно неизвестными. Технические границы формата, доступа и согласованности записи сохраняются.

Дополнительные сценарии для реализации: сумма уровней отличается от ручного итога — показать расхождение и сохранить выбор; заклинаний больше обычного — предупредить и сохранить весь выбранный список; неизвестен класс-источник — сохранить неопределённость без автоматического расхода. Эти сценарии спецификации ещё не реализованы в демонстрационном макете HP и не объявляют OCR готовым.

## Исправление макета21.11: явный unknown

[Ограниченная игровая сверка](sheet-recognition-game-review-80.md) фиксирует независимый P2 и его исправление: сверенное пустое поле можно явно оставить неизвестным, отдельно от0. Это новое поведение макета; историческое17.11 требование заполнить все поля не описывает его текущую версию. Числовой черновик сохраняется при переключении решения, подтверждение сбрасывается, unknown-maxHP не становится0. Макет по-прежнему не создаёт героя, не сохраняет данные после reload и не принимает nullable-схему #81/#82. #80/M0 и зависимости остаются открытыми.

## EXIF в исходном JPEG · 24.11.2026

Корпус содержит два варианта одной вымышленной страницы. У JPEG без ориентации пиксели записаны боком и нужен ручной поворот.
