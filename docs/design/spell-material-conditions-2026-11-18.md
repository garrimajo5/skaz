# Материальные условия заклинаний — контракт и образец #34

18.11.2026. Роли: контент → frontend. Статус: проверенный частичный артефакт; не функция production и не изменение формата игры. Runtime остаётся41da232. Предложение данных — `catalog/spell-materials.proposal.json`; оно не входит в allowlist bundled-catalog.

## Игровой результат

В карточке отдельно видны стоимость материалов и расход. Дорогой компонент не считается расходуемым автоматически. При частичном расходе названа сохраняемая часть; при отложенном — момент и условие. «Цена в правиле не указана» отличается от «Стоимость не уточнена»; ни одно не означает бесплатно. Неизвестные сведения не означают отсутствие M.

Наличие материалов, разрешение фокусировки, особенности класса и личные договорённости здесь не проверяются. Нет списаний, добавления вещей, изменения хитов/ячеек или запрета сотворения. Правила информируют; ручной путь остаётся доступен. Это справочный слой, а не новый расходный механизм.

## Источник и полнота

Общий принцип M — стр.102; отдельные страницы/хеш полного извлечённого описания записаны для каждого примера. Атрибуция и описание преобразования включены в proposal. Полный английский текст в этот PR не копируется.

319 текущих заклинаний,184 с M. Разобраны12: Identify,Feather Fall,Fireball,Find Familiar,Continual Flame,Revivify,Stoneskin,Protection from Evil and Good,Warding Bond,Clone,Instant Summons,Astral Projection. Осталось172 записи с M. Остальные135 не имеют M и не считаются пропуском материальных условий. Это не полный каталог2014 и не расширение покрытия артов.

`retained` требует ручной сверки полного описания и общего правила, а не отсутствия слова consumes в заголовке. Instant Summons показывает почему: расход описан позднее в основном тексте. Исходное извлечение закреплено хешем; автоматическая сверка подтверждает идентичность доказательства, не правильность перевода. Независимый read-only проверяющий сверил все12 с извлечением без расхождений.

## Схема предложения

- Верхний kind=`spell-material-reference-proposal`,schemaVersion1,ruleset2014,statusreview. Это версия предложения, НЕ catalog.schemaVersion.
- На строке: стабильный id, имя, SHA256 нормализованной записи каталога, страницы, SHA256 полного извлечённого описания, дата проверки.
- materials.description — предметы и условия; note — дополнительные условия.
- price.kind: unknown / not-stated / stated. Для stated обязателен текст с полными условиями, для остальных произвольная цена запрещена. Числового total нет: нельзя потерять «каждое кольцо», «на каждое существо», отдельный сосуд и варианты материала.
- consumption.kind: unknown / retained / consumed / partial / conditional. Для всех кроме unknown обязателен поясняющий текст. Категория — средство отображения, не команда списания.
- Хеш всей записи предотвращает автоматическое применение справки к изменённому личному варианту с тем жеID. Изменение записи требует повторной сверки. Это намеренная консервативность; несовпадение не запрещает пользовательское действие.

## Подключение к приложению — следующий шаг backend/frontend

Текущий validateCatalog и вложенный каталог export/import принимают точный schemaVersion1. Нельзя незаметно расширять его полями материалов и выдавать старый формат за совместимый.

Для первого подключения предлагается отдельный read-only справочный слой по точному хешу нормализованной записи; сам сохранённый каталог и файлы переноса остаются прежними. Сервер получает текущий разрешённый контекст пользователя и возвращает справку только для совпадающей версии. Личный изменённый текст с тем жеID не наследует общие условия автоматически. Клиент показывает неизвестное при несовпадении/отсутствии/ошибке; не блокирует чтение или действие.

Пакетный запрос только для видимых карточек, не по одному запросу на каждый элемент и не для всего каталога при старте. Защита входа/изоляция контекста сохраняются. При переключении пользователя, поиске и открытом диалоге поздний ответ не меняет чужую выдачу и не теряет фокус. Справка общедоступного источника не получает персональных отметок мастера. Контракт endpoint и реализация ещё не добавлены; сначала независимый backend-обзор этого решения. Будущий импорт собственных материальных условий потребует отдельной явно версионированной схемы/переноса, а не побочного изменения этого слоя.

DoD подключения:12проверенных примеров доступны в настоящих карточках; ошибка/несовпадение дают неизвестное; записи безM не получают лишних предупреждений; цена/расход доступны через aria-describedby; личный override/аккаунты/late response и старые export/import покрыты тестами; браузер/Android/независимая QA и защищённый выпуск. До этого proposal не засчитывается как опубликованная функция.

Контент: разбор полного тела предотвратил неверный «сохраняется» для Instant Summons; предложение планировщику — всегда включать один пример с расходом вне заголовка. Польза высокая, затраты малы, риск не покрыть другие условные механики остаётся.
Frontend: первый образец имел ошибкуCSS-сетки и неверный путь ассетов; исправлено по браузеру, добавлен HTTP-тест ресурсов. Независимое ревью поймало потерю доступного описания. Предложение — испытать общий helper справочных описаний на следующем подключении; не копировать целиком карточку в новый компонент. Общие инструкции не менялись, решения планировщика ожидаются.
