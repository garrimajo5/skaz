# Быстрый доступ при одновременном изменении ячейки и загрузке списка

Ориентир [Figma 3:3](https://www.figma.com/design/hskYV8FnfqELPW99dVMHXw/Skaz?node-id=3-3) и сохранение положения элементов из [визуальных гайдлайнов](../visual-guidelines.md#прототип-интерфейса). Исходная версия `8e7890d`, данные двух игровых списков и ячейки вымышленные.

| Сценарий | Проверка и результат |
| --- | --- |
| Книга или расходники временно недоступны | На исходной версии иконка готовой карточки возвращалась к заглушке после нажатия ячейки. Теперь строка, картинка, фокус, координаты и прокрутка остаются прежними во время записи и после подтверждения. Сообщение о временной недоступности и кнопка повтора остаются в недоступном разделе. |
| Одна секция уже повторно загружается | Если ячейка изменилась во время чтения, приложение дождалось записи и сделало ровно одно новое чтение изменившегося снимка. Готовая секция не пересоздавалась. Ответ прежнего запроса с 409 не очистил её. |
| Запись ячейки оборвалась | После обрыва чтение снова доступно для явного повтора. Очередь сохранена. Ручная отправка повторила ту же команду, сервер подтвердил одну ревизию, затем недоступный раздел снова открылся. |
| Отказ в доступе у актуального запроса | Актуальный 403 очистил оба игровых списка. Разделы от прежнего снимка данным нового контекста не становятся. |

48 измерений в Edge на 1512×982, 820×1180, 390×844 и 844×390 во всех трёх темах. Для этой матрицы задержки задавались на границе чтения списка. Ещё восемь сценариев проверены через настоящие маршруты HTTP. В них задерживали начальное чтение или повтор, прерывали отправку, подавали старый 409 и актуальный 403. На 390×844 ячейку нажимали касанием, на 1512×982 использовали Enter. Windows: 243 целевых теста и `npm run check:play`.

[До](resource-partial-252/before.png) · [После](resource-partial-252/after.png). Оба кадра на 1512×982 при задержанном подтверждении ячейки. До исправления загруженный образ заклинания временно заменён значком школы.

Рефлексия. Первая проверка с подменой чтения обнаружила пересоздание карточки и не выявила, что повторный запрос может стартовать до записи. Отдельный сценарий на настоящих HTTP-маршрутах подтвердил правильный порядок и отсутствие второго чтения. Для похожих сочетаний записи и чтения стоит сохранять в отчёте последовательность запросов и число изменённых ревизий.
