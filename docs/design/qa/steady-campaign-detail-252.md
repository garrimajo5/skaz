# Открытая карточка кампании при записи ресурсов · #252

На `d54eadb` в Edge 1512×982 и 390×844 открытая карточка заново строилась после расхода ячейки. Прежний узел «К списку персонажей» удалялся при постановке команды в очередь и после ответа сервера. Фокус, поставленный на него во время ожидания, терялся.

Теперь экран переиспользует неизменную разметку. Пока сервер пишет ресурс, кнопки редактирования остаются в прежних местах и обозначены недоступными. Серверная проверка записи и проверка прав при открытии редактора продолжают действовать. Новый результат чтения обновляет карточку. Отказ в чтении очищает предыдущие данные.

| Сценарий | Проверка |
| --- | --- |
| Одна запись ячейки при открытой карточке | 12 сочетаний 1512×982, 1180×820, 820×1180 и 390×844 в трёх темах. «К списку персонажей» и редактор сохраняются. Enter на временно недоступном редакторе не открывает форму. Раскрытая история и фокус возврата сохраняются в ожидании и после ответа. Enter возвращает к списку без новой записи. |
| Другой владелец обновил запись между действием и чтением | 6 сочетаний 1180×820 и 390×844 в трёх темах. Новое описание появляется, прежний узел карточки заменяется. На сервере один расход ячейки и одна отдельная правка записи. |
| Чтение вернуло 403 | Те же шесть размеров и тем. Карточка очищена, показано сообщение о доступе. На сервере учтена только проверенная запись ячейки. |

Полярис, 1512×982, после ответа сервера на одной вымышленной игре. [До](steady-campaign-detail-252/before.png) · [После](steady-campaign-detail-252/after.png).

В Windows прошли `npm run check:campaign-people` и 75 целевых тестов. В Edge использовали отдельные локальные вкладки и игру в памяти, стенд закрыт. Физическая приёмка остаётся в #15.

Рефлексия. Сохранять только название карточки было недостаточно. Проверка раскрытой истории и действия Enter после ответа подтвердила, что игрок продолжает чтение и навигацию с того же места.
