**Остаток по решению о предупреждениях.** В форме палочки паутины ввести 8 при справочном максимуме 7. Поле выдаёт `rangeOverflow` и не принимает отправку. Параллельная проверка той же операции в серверном слое подтверждает 422 с неизменной ревизией и остатком. [Снимок](inventory-details-48/charges-overflow.png).

Следующий шаг для backend и frontend — разделить справочный максимум и допустимое техническое число, затем добавить предупреждение, необязательное согласование и сохранение фактов по экземпляру. Применять общий расчёт к форме, очереди расхода/возврата и серверу. Проверить null, 0, ручное 8/7, отрицательное число, изменение условия, перенос, отзыв доступа и точный повтор. Нумерация экземпляров и прежние значения требуют отдельной проверки совместимости. Issue остаётся открыт.

68/68 тестов инвентаря, чтения карточек, сессий, книги и «Быстрого доступа». Рефлексия QA. Для таких задач полезно проверять предупреждение сразу в двух местах: действием пользователя и серверной командой отдельно. Здесь независимые проверки нашли одинаковую границу.
