# Переключение фильтров быстрых действий

Ориентир [Figma 3:3](https://www.figma.com/design/hskYV8FnfqELPW99dVMHXw/Skaz?node-id=3-3), сохранение положения элементов из [визуальных гайдлайнов](../visual-guidelines.md#прототип-интерфейса). Исходная версия `ddbed93`. Игра, заклинания и расходники вымышленные.

В исходном варианте переход «В бою» → «Вне боя» заменял уже показанный расходник, его картинку, строку фильтров, контейнер списка и последнюю заметку. После правки эти пять элементов остаются на месте, меняется состав строк заклинаний. Выбранный фильтр сохраняет фокус, горизонтальная прокрутка фильтров остаётся на том же месте. Прокрутка списка заклинаний сбрасывается при явном выборе другой группы. Количество видимых строк может изменить высоту секции.

В Edge проверены 15 сочетаний: 1512×982, 820×1180, 1180×820, 320×640, 844×390, Полярис, Уголь и Атлас. После «Вне боя» появляется «Починка», раньше показанный «Луч холода» скрывается. Обратный переход восстанавливает список боя. На 320×640 во всех темах проверен переход через пустую группу «Бонусное» и обратно. Ревизия игры прежняя. Windows: 55 целевых тестов и `npm run check:play`.

[До](action-scope-252/before.png) · [После](action-scope-252/after.png). Это состояние сразу после смены группы на 1512×982.

Рефлексия. Для фильтра требуются две независимые проверки: список отображает другой набор, а соседние элементы и выбранная кнопка сохраняют свои узлы. Так можно измерять устойчивость при явном изменении данных, даже когда высота списка меняется.
