# Реестр и проверка изображений

## Слой доставки и HTTP

`server/art-library.mjs` принимает проверяемый снимок реестра и публикует
только accepted в индексе, без внутренних путей. `read(url)` создаёт PNG
96/384 по запросу и возвращает байты, MIME и ETag; неизвестный URL, исчезновение
или изменение исходника дают null. URL содержит хеш исходника + рецепта +
кодировщика + роли; это не хеш доставленных байтов, для которых служит ETag.
Исходники не меняются. Уменьшение сохраняет пропорции, без увеличения.

LRU в памяти сервера ограничен 8 MiB по умолчанию; `stats()` показывает
использование, `clear()` освобождает память. Нулевой бюджет отключает хранение.
Это не офлайн-кэш браузера. Подключение UI и браузерный кэш ещё предстоят.
Личные замены сюда передавать нельзя.
Кэшированные байты относятся к проверенному снимку; новый выпуск/отзыв
артов требует нового экземпляра библиотеки. Повторно отдавать старый экземпляр
после изменения реестра нельзя.

`GET /api/art` подключён к обычной защите API (в том числе проверке личности
вкладки). `GET/HEAD /art/common/<key>.png` проверяет вход и доступность аккаунта
перед чтением и перед ответом 304. Для img используется HttpOnly cookie,
поскольку элемент не отправляет X-Skaz-Identity. Общая библиотека не содержит
данных игры или личных изображений. Ответы PNG: nosniff, Content-Length,
ETag, Vary: Cookie, private/max-age=0/must-revalidate. Неизвестные файлы — 404,
другие методы — 405; публичный доступ и обход через произвольный путь отсутствуют.
В локальном общем режиме действует прежнее ограничение Host/Origin.

Реализована инфраструктура #32. Производственное покрытие: 570 пропусков.
09.11 подготовлены 24 локальных кандидата и 48 производных PNG; это ещё
не записи accepted в рабочем манифесте. Выбран рисунок Fireball №19.
Готовый рисунок не создаётся из имени или текста каталога автоматически.

`catalog/art-inventory.json` генерируется из явного bundled-каталога:
319 spell, 49 item, 1 artifact, 201 monster; RU/EN, источник текста и SHA256
точной записи. Варианты сохраняют собственные ID. Источник текста здесь
НЕ является разрешением на использование картинки.

`catalog/art-manifest.json` — редактируемый реестр ассетов (пока entries=[]).
`catalog/art-coverage.json` — воспроизводимый отчёт. Принятые, пилотные,
черновики, заглушки, отсутствующие и все непокрытые ID считаются отдельно.
Новая запись каталога автоматически становится пропуском. Изменение содержимого
требует повторной проверки привязки через contentSha256.

Команды из корня проекта:

```powershell
node scripts/art-registry.mjs --write
node scripts/art-registry.mjs
node scripts/art-registry.mjs --complete
```

Первая обновляет два производных JSON, не перезаписывая манифест.
Вторая проверяет структуру, файлы и актуальность JSON; допустима незавершённая
библиотека. Третья дополнительно требует 100% принятого покрытия и сейчас
ожидаемо возвращает код 1. Пропуски не скрываются успешной структурной проверкой.

## Запись манифеста

schemaVersion=1, ruleset=5e-2014. Для каждого элемента entries:

- id и contentSha256 из inventory, version — положительное целое;
- status: draft / pilot / placeholder / accepted;
- crop: x/y от 0 до 1 — нормализованная точка кадрирования;
- provenance: method (original/generated/licensed), author, source, usage,
  attribution, reviewedBy — непустые строки, сведения именно об изображении;
- review.by / review.evidence обязательны для accepted: кто и где принял вид;
- files.original и files.thumbnail: path, width, height, bytes, sha256.

Файлы: assets/art/…, имена латиницей в нижнем регистре; PNG RGB/RGBA 8 bit,
без interlace, максимум 2048×2048 и 16 MiB, миниатюра максимум 256×256.
Это технические пределы импорта, НЕ целевые бюджеты загрузки: их определит пилот.
Другие форматы сначала безопасно перекодировать; WebP/AVIF доставку определить
в #34 после измерений. PNG проверяется по сигнатуре, структуре, CRC, ограниченной
распаковке, длине строк и фильтрам; произвольные метаданные/активный контент
не разрешены. Неверный SHA, размер, неизвестный ID, дубли, одинаковый оригинал
для разных ID, лишние файлы и выход пути за репозиторий дают ошибку.

## Процесс производства и поставки

Для пилота выбран процесс оригинальных иллюстраций по собственным заданиям,
без копирования чужих картинок и без автоматического импорта dnd.su. Автор
или разрешённый генератор и фактические условия фиксируются ПОСЛЕ создания,
не подменяются лицензией SRD. Платный генератор сейчас не выбран и не разрешён;
при необходимости отдельное решение, без покупок и вызовов за пользователя.
Визуальная приёмка и юридическое разрешение не доказываются непустой строкой:
валидатор проверяет наличие свидетельств, человек проверяет их содержание.

В Git — манифест, ограниченные по размеру одобренные оригиналы и миниатюры,
нужные для воспроизводимого выпуска. Слои/промежуточные генерации не коммитить;
их хранение определить при пилоте без нового платного сервиса. Общий размер
партии проверять до коммита. Личные арты остаются приватными данными вне Git.
Реестр пока не подключён к runtime: API и пользовательские игры не изменены.

## Воспроизводимая подготовка пилота (09.11.2026)

`node scripts/art-derivatives.mjs` читает candidates.json и сверяет SHA256
каждого исходника до записи результатов. Вход ограничен data/art-pilot-v1,
проверяются уникальность ID, PNG CRC/структура/размер и все пять фильтров строк.
caBX допускается только декодером исходников: он остаётся в оригинале.
Производственный inspectPng не ослаблен. Декодированные пиксели пересчитываются
по площади с premultiplied alpha, заново кодируются в RGBA PNG; цветовые
sRGB/gAMA/cHRM сохраняются. Это техническое уменьшение, не художественная ретушь.

Выход data/art-delivery: 96 px (миниатюра) и 384 px (карточка), пропорции
сохранены, увеличения нет. Имена содержат хеш результата. manifest.json
содержит derivedFrom (SHA256 оригинала), recipe, версии Node/zlib и отдельные
размеры/хеши каждого файла. Повтор на тех же Node/zlib даёт идентичные файлы;
между версиями компрессора побайтовая идентичность не обещается. Оригиналы
и старые результаты не удаляются. Ненужные результаты не обслуживаются:
стенд использует только текущий manifest.json и проверяет свежесть исходника.

Измерения 24 образцов: thumbnail суммарно 296991 байт, максимум 19951;
card суммарно 3977791 байт, максимум 279867. Предварительные потолки пилота:
20 KiB/thumbnail, 280 KiB/card. Это файловые размеры, не измеренная начальная
загрузка игры или офлайн-кэш. Такие измерения ещё нужны в #33/#34.

Просмотр: `node scripts/art-pilot-server.mjs`, затем
`/all?set=claude&mode=prepared` или `/all?set=creatures&mode=prepared`.
Без mode=prepared показываются исходники. Это отдельный стенд, не игровые
компоненты; runtime, API, кэш и VPS на этом этапе не меняются. Кандидаты и
производные пока локальны; перенос одобренных файлов в assets/art и запись
производственного манифеста — следующий шаг. Счётчик accepted остаётся 0/570.
