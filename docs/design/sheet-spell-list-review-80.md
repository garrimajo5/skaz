# Сверка списка заклинаний — #80

[Прототип](prototypes/sheet-review-80.html), пример «Мультикласс и раздельные ячейки».
На синтетическом листе указаны волшебник 3, колдун 2 и два раздельных источника
ячеек. Для упражнения под таблицей добавлены «Щит» и кандидат «Туманный шаг».
Это проектное предложение для [#82](https://github.com/garrimajo5/skaz/issues/82).
Прототип формирует снимок в памяти браузера. Заведение героя, OCR, перенос и
запись на сервер в этом шаге отсутствуют.

## Снимок сверки

| Выбор игрока | Значение поля `spells` | Что видно в будущем профиле |
| --- | --- | --- |
| Выбор ещё не сделан | Запись отсутствует. Группу пока нельзя подтвердить. | Продолжить сверку. |
| Оставить список неизвестным | `null`, `left-unknown`, `manual-unknown` | «Список пока неизвестен». Доступен ручной ввод. |
| Подтвердить отсутствие заклинаний | `{coverage:"complete",rows:[]}` | «Заклинаний пока нет». |
| Принять доступную часть | `{coverage:"partial",rows:[…]}` | Сверенные записи видны сразу, оставшиеся неизвестны. |
| Сверить весь список | `{coverage:"complete",rows:[…]}` | Виден весь подтверждённый список, включая вручную оставленные неизвестными атрибуты отдельных строк. |

Указатель полноты относится к **списку в охваченном источнике**. Выбор
«Сверить весь список» требует решения по каждой показанной строке, а отдельные
свойства подтверждённой строки можно явно оставить неизвестными. Выбор пустого
списка означает, что игрок сознательно исключил кандидатов целиком. Пока идёт
сверка, можно вернуть частичный режим и продолжить с прежними выборами.

```json
{
  "fieldId": "spells",
  "selection": "corrected",
  "value": {
    "coverage": "partial",
    "rows": [
      {"rowId":"example-shield","name":"Щит","source":"wizard","location":"book"},
      {"rowId":"example-misty-step","name":"Туманный шаг","source":null,"location":"prepared"}
    ]
  },
  "provenance": "manual-correction"
}
```

Здесь название «Туманный шаг» и отметка в листе сверены, класс не установлен.
Совпадение с каталогом может уточнить карточку заклинания. Оно не даёт ни
класс-источник, ни право автоматически списать ресурс. «Щит» в книге сохраняется
как справочная запись для подготовки. Неизвестные строки не скрывают уже
сверенные записи и не обнуляют ручные ячейки. «Подготовлено» и наличие в книге
могут совпадать. Поле `location` в примере хранит одну отметку исходного
листа. Рабочая схема должна хранить эти признаки независимо, для каждого
источника. Один и тот же ID каталога может встретиться у нескольких источников.

## Передача #82 и будущему OCR

1. Связать каждую строку со стабильным ID внутри подтверждённого снимка.
   Ручной выбор источника сверять с серверной строкой класса, предметом или
   иным известным источником героя. Для совпавших названий показывать источник
   рядом со строкой. При неизвестном источнике сохранить название, отметку
   и происхождение. Показать способ вручную уточнить источник.
2. После поворота/замены страницы сохранить ручные решения в черновике и
   снять подтверждение. Новый снимок должен ссылаться на актуальную ревизию.
   Отложенная строка остаётся в черновике. В профиль попадают проверенные строки
   с признаком частичного охвата и явно неизвестными свойствами.
3. Сохранять пользовательский ввод при игровом отклонении и дать пояснение.
   Для автоматического действия использовать общий игровой расчёт после
   выбора источника и проверки известных входов. Чужой ID, неподдерживаемая
   форма данных и устаревшая ревизия требуют технического ответа без записи.
4. Проверить сохранение, точный повтор и перенос каждой формы из таблицы.
   Старый v15 без признака охвата сохраняет свою прежнюю семантику. При
   несовместимом экспорте сообщить о потере представимости до записи файла.
   Версию формата и обратное чтение согласовать по
   [матрице v15](../sheet-profile-format-boundary-80.md).

## Проверки

`npm run test:sheet-review` выполнил scoped noEmit и 25 тестов. Новые
[поведенческие проверки](../../tests/sheet-review-flow.test.mjs) покрывают
неизвестный и пустой списки, частичный список с сохранением отдельных групп
ячеек, выбор источника, сброс подтверждения и отмену смены примера.

В Edge на отдельном локальном стенде пройдены те же переходы от неизвестного
до полного списка с неизвестным источником одной строки. Проверены Полярис
390×844, Уголь 820×1180 и Атлас 1180×820. Смена состояния клавишей сохранила
фокус, сняла подтверждение и скрыла прежний результат. Горизонтального
переполнения и ошибок страницы не было. Проверены сборка и синтаксис.
Размеры планшета проверены через viewport Edge. Android и физический планшет
для добавленной секции ещё предстоят.
