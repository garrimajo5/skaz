# Визуальные образцы сверки листа — #80

Корпус содержит 21 оригинальный синтетический файл для проектирования UX. Личных листов и скопированных официальных форм здесь нет.

- 10 случаев из `../sheet-review-cases.json` представлены PNG; конфликт страниц имеет две страницы.
- Дополнительно: текстовый PDF, PDF со сканом без текстового слоя, двухстраничный конфликт, повёрнутый JPEG, намеренно нечитаемый JPEG, английская двухколоночная форма PNG/PDF, JPEG с EXIF, обрезанный снимок без подписей к хитам и PNG с колонками SLOTS TOTAL / SLOTS EXPENDED.
- `manifest.json` связывает файлы, SHA-256, размеры, ожидаемые значения и области полей. Координаты относятся к прямому PNG; повёрнутый JPEG сначала исправляется на 90° по часовой стрелке. PDF использует пропорциональные координаты A4.
- Пустые текущие хиты и количество предмета намеренно не равны нулю. Для испорченного JPEG ожидается отказ от уверенного чтения, а не угадывание значений.

Генерация: `python scripts/build-sheet-visual-fixtures.py` (Pillow, ReportLab). Шрифт задаётся `SKAZ_FIXTURE_FONT`; по умолчанию Arial в Windows или DejaVu Sans в Linux. Его хеш записывается в manifest; другой шрифт может изменить байты. Проверки: `node --test tests/sheet-visual-fixtures.test.mjs` и `python tests/test_sheet_visual_files.py` (Pillow, pypdf).

Все PDF отрендерены и просмотрены; проверены страницы, размеры A4 и наличие/отсутствие текстового слоя. PNG просмотрены контактным листом. Эти исходники создают контролируемые случаи, но не представляют разнообразие настоящих листов, фотографий и рукописного текста. Наклонная печатная подпись не считается рукописью. Повреждённые/зашифрованные PDF и лимиты декодирования — отдельная backend-проверка.

Независимая сверка ожидаемых значений и согласование форматов, лимитов, хранения и правил ещё нужны. Корпус сам по себе не переводит #84/#97 в Ready.
