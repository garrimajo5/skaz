# Бюджеты доставки артов

Измерение 09.11.2026, 80 принятых ID. Команда:

```sh
node scripts/art-budget.mjs --write
node scripts/art-budget.mjs --check
node --test --test-isolation=none tests/art-budget.test.mjs
```

Для другой платформы/кодировщика сохранять отдельный снимок, например:

```sh
node scripts/art-budget.mjs --report=catalog/art-budget-linux.json --write
node scripts/art-budget.mjs --report=catalog/art-budget-linux.json --check
```

Windows Node 26 и серверный Linux Node 24 используют разные версии zlib;
их отчёты не обязаны побайтно совпадать. Ошибка `--check` при чужом кодировщике
не обходится удалением версии: измеряется и сохраняется отдельный отчёт.
В текущем прогоне числовые размеры на обеих платформах совпали; отличается
encoder. Linux-снимок находится в `catalog/art-budget-linux.json`.

Отчёт `catalog/art-budget.json` проходит через настоящий `createArtLibrary`:
сначала строгая проверка реестра/PNG/происхождения, затем фактические байты
перекодированной доставки. Версия zlib и рецепт записаны; при смене кодировщика
отчёт нужно пересоздать и проверить. Команда не обращается к базе кампаний.

| Роль | Количество | Сумма байт | Максимум | p95 | Лимит файла |
| --- | ---: | ---: | ---: | ---: | ---: |
| Миниатюра 96 px | 80 | 1097842 | 21187 | 19951 | 32768 |
| Карточка 384 px | 80 | 15128020 | 299596 | 279867 | 393216 |

Лимиты 32 KiB и 384 KiB — проверяемые верхние границы текущего PNG-процесса,
а не обещание размера WebP. Выход за бюджет делает команду и регрессионную
проверку неуспешными; порог не увеличивается автоматически при новой партии.
Полный набор: 160 уникальных файлов, 16225862 байта. Серверный LRU ограничен
8388608 байт; рост библиотеки означает вытеснение, а не рост этого лимита.
Отдельный тест измеряет всю реальную библиотеку при кэше всего 32768 байт.

Программный `measureArt(library,{ids})` позволяет измерить конкретный набор:
повтор ID не умножает файлы, повтор URL считается один раз в uniqueBytes.
Отсутствующее принятое изображение вызывает ошибку, а не занижение суммы.
Таблица ролей учитывает логические изображения, uniqueBytes — уникальные URL.
Пустой набор имеет нулевой размер. Карточки измеряются для аудита — это
не команда на предварительное скачивание всей библиотеки браузером.

## Браузерный кэш — реализовано 09.11.2026

Просмотренные общие миниатюры сохраняются в CacheStorage: максимум 2 MiB и
128 файлов, LRU под Web Locks для нескольких вкладок. URL содержит SHA версии;
новый hash не получает старое изображение. Крупные карточки не сохраняются.
Ключ хранилища включает ID пользователя; выход/блокировка очищает его кэш,
отзывает Blob URL и исключает запоздалую запись. Данные игры и личные файлы
сюда не попадают. В настройках доступны размер, число файлов и очистка.
Quota/private-mode/отсутствие Web Locks оставляют обычную загрузку и заглушки.

На вымышленной игре браузер и Android загрузили две видимые миниатюры;
после отказа доставки артов (503) они показаны из кэша без новых PNG-запросов.
Очистка в настройках дала 0 файлов / 0 KiB. Это моделирование отказа доставки,
не физическое отключение Wi-Fi. Проверены настройки на 390×844, 820×1180,
1180×820, три темы и очистка клавиатурой. Кэш не скачивает всю библиотеку.

Индекс /api/art остаётся в памяти страницы. Холодная перезагрузка приложения
требует сети; кэш не означает полностью автономный запуск. При уже открытой
странице сохранённые общие миниатюры доступны без повторной доставки.

## Начальная загрузка на Android — 09.11.2026

Отдельный новый origin :4193, Chrome Android Studio Pixel_8, 2400×1080,
вымышленная игра /#play. Сервер считал байты тел ответов write/end; счётчик
не сохранял cookies, пароли или содержимое API. Первый заход: 40 запросов,
733093 байта (оболочка/шрифты 676877, API 30599, две миниатюры 25617).
Повторное открытие: 37 запросов, 707428 байт, изображения 0 запросов/0 байт.
Оболочка/API продолжают загружаться. Из 112 PNG запрошены только два.
Числа и ограничения: [art-network-android.json](art-network-android.json).
Это исходный замер сценария, не универсальный предел размера любой кампании.

Повторяемый стенд: `node scripts/art-load-fixture.mjs 4193`, затем
`adb reverse tcp:4193 tcp:4193` и открыть в Chrome Android
`http://127.0.0.1:4193/#play`. Снимки счётчиков — GET `/qa-metrics`;
сам endpoint в подсчёт не входит. Снять первый, повторно открыть адрес,
вычесть первый снимок из второго. Для холодного захода использовать новый
порт/origin; не очищать пользовательские данные Chrome. Стенд использует
только SQLite :memory:, bundled-каталог, Fireball, зелье и плащ ската;
не принимает путь к БД и слушает только 127.0.0.1. По завершении Ctrl+C и
удалить свой adb reverse. Имена/ID вымышленной игры и текущая версия клиента
могут менять общий размер API; проверять категории и PNG отдельно.
Тест `tests/art-load-fixture.test.mjs` сверяет реально полученные байты,
HEAD, исключение endpoint и независимость снимка счётчиков.

## Что этим не проверено

Нет замера задержек, FPS, декодирования или физического iPad. Числа первого
открытия не включают HTTP/TLS overhead и сжатие VPS. Таблица PNG выше измеряет
байты PNG в памяти сервера, без HTTP-заголовков/TLS/сжатия оболочки страницы.
Не заявляется «офлайн готов». #33/#34/#39 остаются открытыми.

Следующий шаг #34/#39: расширить матрицу измерений другими раскладками
и итоговой проверкой всех поверхностей с расширенным набором. Все арты сразу
автоматически не загружать. Личные изображения этим общим реестром не покрыты.
