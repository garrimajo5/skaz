## Порядок и происхождение

В историческом scope современные демонские наблюдения имеют sourceIds=[158,129], а effective identity review использует отсортированный[129,158]. Оба массива показаны отдельно; два различия порядка не объявлены ошибкой исходника и не исправляются. Для каждого original-source claim сохранены observationId/sourceId/исходный индекс массива. Порядок не трактуется как приоритет публикации. Общий source129 не доказывает тождество MPMM и старого текста; MTF-плашка остаётся отдельным непроверенным утверждением о версии.

## Проверки и границы

Девять Node-тестов проверяют воспроизведение, topology/версии, сохранность исходного порядка, потерю/повтор наблюдений, изменение принятого source evidence и отсутствие мутации. Пять входов закреплены SHA. CLI review-d03-reference-relationships-2014.mjs по умолчанию только проверяет; запись — явным --write в фиксированный артефакт.

acceptedForReferenceRelationship:true относится только к данным отношениям на проверенном отпечатке. Top-level accepted/complete:false,canonicalUnitsAccepted0,denominator:null. Canonical count группы не назначен; автоматические merge/split/миграция выключены, runtime/персонажи не меняются. Визуальный UI/Android/выпуск приложения неприменимы, M0/issue77 открыты.

Следующий шаг — независимый обзор реализации; затем точное первичное сопоставление версий/вариантов либо источник издательского digital-record overlap. Уже проверенные имена/состояния не повторять как новую работу.

Рефлексия: исходный scope и effective review имеют разный порядок двух одинаковых наборов источников. Строгое сравнение только одного массива могло бы либо ошибочно отклонить историю,либо переписать её. Предложение — сохранять оба представления и проверять множество отдельно от порядка; польза корректная трассировка,затраты один explicit field,риск ложного приоритета снят false-флагом. Общие инструкции не изменены.
