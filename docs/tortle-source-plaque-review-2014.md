# Tortle184: буквальная вторичная атрибуция

Refs #77, роль content. После свода D02 проверено конкретное наблюдение без sourceIds: `dndsu:race:184`. [Новый слой](../catalog/tortle-source-plaque-2014.json) сохраняет исходный пустой массив, routing и прежний отчёт без изменений.

Один ограниченный публичный запрос [вторичной страницы](https://dnd.su/race/184-tortle/) дал HTTP200 без перенаправления. SHA записан в отчёте. В непосредственном блоке параметров статьи строка «Источник» буквально называет The Tortle Package; она отличается от похожего заголовка в навигации/метаданных. Скрипт проверяет точный og:url, область статьи и единственность строки источника; чужой/дублированный источник не выбирается автоматически.

Это новое свидетельство вторичной атрибуции, не первичный текст/версия и не числовой sourceId. Не назначать158 из соседней MotM-карточки, не подменять исходный sourceIds=[], не объединять версии. FullRules/errata/rights остаются unverified, accepted/complete:false, denominator:null. Из HTML извлекается только название источника; тексты правил не включены в Git. Runtime и профиль не меняются, browser/Android/выпуск приложения неприменимы.

Проверки: восемь Python-тестов, реальное извлечение из сохранённого HTML и точные два входных SHA. Воспроизведение: `scripts/review-tortle-source-plaque-2014.py --html <снимок> --output <новый JSON>`; исходный HTML не может быть перезаписан. Следующий шаг — первичное сопоставление именно этой публикационной версии и отдельный статус прав, не повторный поиск названия.

Рефлексия: первый парсер ошибочно ожидал один блок params во всей статье. Реальная страница содержит несколько таких блоков; выбор ограничен непосредственными параметрами и единственной строкой источника, а неоднозначность отклоняется. Предложение — сохранять такой отрицательный пример при следующем парсере; польза в предотвращении ложного свидетельства, затраты один короткий тест, риск низок. Общие инструкции не меняются.
