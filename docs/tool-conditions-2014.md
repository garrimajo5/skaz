# Условия использования инструментов SRD 2014 — #77

`catalog/srd51-tool-conditions-2014.json` содержит предложения девяти разделов правил по [SRD 5.1, страницы 70–71](https://media.wizards.com/2023/downloads/dnd/SRD_CC_v5.1.pdf): ремесленные инструменты, наборы для грима, подделки, игры, травничества, музыкальные инструменты, инструменты навигатора, набор отравителя и воровские инструменты. Источник закреплён SHA, атрибуция CC BY 4.0 включена.

35 ссылок ведут к существующим предложениям предметов из `equipment-identity-reconciliation.json`: 17 ремесленных, 2 игровых, 10 музыкальных и 6 отдельных наборов. Это не новые предметы и не доказательство наличия runtime-карточек. Два игровых набора из Basic Rules не добавляются в область таблицы SRD без отдельного свидетельства.

Владение инструментом относится к подходящей проверке характеристики. Конкретная характеристика зависит от задачи; приложение не должно молча выбирать Ловкость для всех инструментов или считать владение автоматическим успехом. Для ремесленных, игровых и музыкальных инструментов каждый тип имеет отдельное владение.

Травник: обычное правило требует владения набором для изготовления противоядия и зелий лечения. Будущая реализация показывает отклонение и сохраняет ручное действие; личное исключение не меняет справочник. Время и цена изготовления в этом фрагменте не заданы, автоматического изготовления нет.

Бард может использовать музыкальный инструмент как фокусировку. Это отдельное условие, которое не предоставляет заклинания и не отменяет остальные требования колдовства. Навигационные инструменты описаны для моря; правило не расширено на любую навигацию.

Проверки: `node --test tests/srd-tool-conditions.test.mjs` — 3/3. Проверяются уникальные существующие ID и SHA, отдельные владения, контекст характеристики, ручной путь, отсутствие автоматических выдач/списаний/успеха и непроверенных параметров изготовления. Независимый разрешённый read-only reviewer сверил изображения SRD70–71 и подтвердил все 35 ссылок отдельным вычислением; блокеров нет. Тесты reviewer самостоятельно не запускал.

`accepted=false`, `runtimeImported=false`, `complete=false`. Это проверенное предложение ограниченного фрагмента для дальнейшей работы; полнота #77/M0 и выпуск приложения не заявлены. Полные правила изготовления, происхождение владений, конкретные проверки и прочие условия колдовства остаются отдельными зависимостями. Браузер/Android/VPS к этой неподключённой партии неприменимы.

Рефлексия: разделение обычного правила и поведения интерфейса позволяет сохранить точность SRD без запрета личных договорённостей. Предложение планировщику — применять ту же пару полей к следующему фрагменту с требованиями; польза — меньше скрытых игровых блокировок, затраты — явное описание ручного пути, риск — структурные тесты не заменяют смысловое ревью.
