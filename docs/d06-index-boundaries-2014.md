# D06 · границы индексов SKT, IMR и Fiendish Folio

Сверка для [#77](https://github.com/garrimajo5/skaz/issues/77) сохраняет ID и принадлежность карточек к источникам. Статусы полного текста, канонической связи и использования материалов остаются открытыми.

## Storm King’s Thunder

В цифровой выдаче 105 карточек. У 85 указан SKT, у 20 указан Monster Manual 2014. Последние сохранены со ссылками на исходные наблюдения Monster Manual. Четыре карточки Yuan-ti Malison различаются по URL.

Из 94 наблюдений dnd.su по SKT для 25 пока нет кандидата по имени. Среди карточек издателя такой кандидат отсутствует у 16. В отчёте сохранены 3 изученные группы вариантов, 6 цифровых меток вариантов великанов, 4 строки с пустым CR, 1 заголовок приложения и 2 строки, видимые только в индексе.

Cloud Giant Child имеет CR 0 и размер Medium. Отдельная карточка Young Cloud Giant имеет CR 5 и размер Huge, а её имя совпадает с наблюдением 7728. Оснований объединять две карточки по общему имени великана нет. Пустое значение CR остаётся неизвестным. [Наблюдение Young Cloud Giant](https://dnd.su/bestiary/7728-young-cloud-giant/).

Оглавление подтверждает расположение Hulking Crab, New Giant Options, Tribal Spells и Appendix D. При прямой проверке три карточки без CR перенаправили в магазин, Vaasha завершилась тайм-аутом. Состав четырёх именных карточек описан ниже. Остальные связи вариантов и точный список 22/24 ещё проверяются. Список относится к шаману и не добавляет отдельную единицу существа, его состав нужен в M4. [Оглавление SKT](https://www.dndbeyond.com/sources/dnd/skt), [официальные исправления](https://www.dndbeyond.com/sources/dnd/sae/storm-kings-thunder).

### Именные карточки штормовых великанов

На печатной странице 256 (страница 10 PDF) находится один общий блок Storm Giant и четыре именные карточки для главы 12. Издатель предлагает выдать каждому игроку копию общего блока вместе с одной именной карточкой. Nimir, Orlekto, Shaldoor и Vaasha добавляют индивидуальные навыки и сведения для отыгрыша. Все четыре строки остаются в цифровом индексе со своими URL и пустым CR. В приложении D это четыре именных дополнения к одному блоку. Число канонических единиц и эквивалентность блоку Monster Manual 2014 подлежат отдельному решению. [Официальное приложение D](https://media.wizards.com/2016/dnd/downloads/SKT_AppD.pdf#page=10).

[Машиночитаемая сверка](../catalog/skt-appendix-d-npc-composition-2014.json) хранит страницы, SHA-256 исходника и четыре связи. Скачанный PDF весит 1 497 598 байт. Для воспроизведения скачать PDF по ссылке, сверить SHA с реестром и открыть страницу 10. Разрешение в полях страницы касается копирования для домашней игры. Основание для публикации текста в СКАЗ остаётся открытым.

Полная сверка строк без CR охватывает все 22 цифровые карточки SKT. На печатных страницах 247–255 есть по два отдельных блока именованных NPC. Все 18 имён сопоставлены по точному названию с цифровой строкой SKT и исходным наблюдением 132. Страница 256 добавляет четыре именных дополнения, описанных выше. Пустой CR сохранён у всех 22 строк, печатная структура остаётся самостоятельным свидетельством. [Постраничный реестр](../catalog/skt-appendix-d-npc-index-2014.json), [официальное приложение D](https://media.wizards.com/2016/dnd/downloads/SKT_AppD.pdf).

### Базовый штормовой великан и общий блок NPC

AC 16 и 230 HP совпадают в четырёх опубликованных блоках. Для выбора версии этого недостаточно. У печатного NPC из приложения D нет CR, общего списка навыков и мировоззрения в общем блоке. Навыки и мировоззрение находятся на четырёх именных дополнениях. У SRD и отдельной Legacy-карточки есть собственные CR 13 и набор навыков. В цифровой главе Basic Rules есть мировоззрение, а полей CR и навыков в этом блоке нет. [Печатное приложение D](https://media.wizards.com/2016/dnd/downloads/SKT_AppD.pdf#page=10), [SRD 5.1, страницы 313–314](https://media.wizards.com/2023/downloads/dnd/SRD_CC_v5.1.pdf#page=313).

| Источник | Восстановление удара молнии | Заклинания |
| --- | --- | --- |
| SRD 5.1, страницы 313–314 | 5–6 на к6 | Врождённая особенность, четыре заклинания без лимита, два по три раза в сутки каждое. |
| SKT, печатное приложение D, страница 256 | Короткий или продолжительный отдых | Врождённая особенность, тот же список и пределы, что в SRD. |
| Эррата SKT, страница 256 | В поправке не указано | Действие. Feather Fall исключено, два суточных заклинания применяются по одному разу каждое. Control Weather явно занимает одно действие. |
| Глава Basic Rules (2014) | Короткий или продолжительный отдых | Совпадает с поправкой SKT по перечисленным полям заклинаний. |
| Отдельная Legacy-карточка 17026 | 5–6 на к6 | Совпадает с поправкой SKT по перечисленным полям заклинаний. |

В заголовке главы Basic Rules ссылка ведёт на карточку 17026. Значения перезарядки у двух поверхностей одного сайта различаются. Для переноса полей используй URL конкретной поверхности и издание. Поправку к заклинаниям читай как изменение одного блока с собственным указателем. [Эррата SKT](https://www.dndbeyond.com/sources/dnd/sae/storm-kings-thunder#StormGiant), [глава Basic Rules](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/monster-stat-blocks-s), [карточка 17026](https://www.dndbeyond.com/monsters/17026-storm-giant).

Если при проверке восстановления выпало 5 на к6, потраченное действие по SRD снова доступно. Для печатного NPC бросок сам по себе ничего не восстанавливает. При проверке доступности ежедневных заклинаний учитываются два отдельных счётчика. Итог зависит от выбранного источника. Эти примеры предназначены для будущих тестов при выборе версии.

[Реестр границ источников](../catalog/skt-giant-source-boundaries-2014.json) сохраняет 5 представлений, 4 именных дополнения, 6 ссылок на варианты и SHA-256 семи свидетельств. У всех шести цифровых вариантов CR совпадает с соответствующей базой SRD. Для четырёх печатная страница подтверждает количество дополнительных действий. Для двух остальных это поле неизвестно. Сходство CR и ссылка между страницами не доказывают эквивалентность правил, автоматическое объединение отключено.

Для Cloud Giant исправление Monster Manual 2014, страница 154, меняет спасбросок Телосложения с +9 на +10. В базовом SRD зафиксировано +10. Для варианта SKT значение не установлено. При открытой проверке обе карточки Cloud и Fire Giant (variant), а также ссылки на главы 8 и 9 и раздел «New Giant Options» ведут в магазин. Открытая страница 246 сохраняет два фрагмента без подтверждённого родителя. [Эррата Monster Manual 2014](https://www.dndbeyond.com/sources/dnd/sae/monster-manual-2014#CloudGiant), [вариант Cloud Giant](https://www.dndbeyond.com/monsters/324263-cloud-giant-variant), [вариант Fire Giant](https://www.dndbeyond.com/monsters/324266-fire-giant-variant).

Чтобы повторить сравнение, сохрани семь открытых страниц/PDF из поля `sources` с указанными именами вне Git и выполни `python scripts/audit-skt-giant-source-boundaries-2014.py <папка> --verify` с pypdfium2. Команда сравнивает сохранённые байты и наблюдения с реестром. Если свежая HTML-выдача изменилась, запусти без `--verify` и сверяй новые поля и хэши отдельным срезом. Для PDF работают закреплённые хэши. Для зрительной проверки открой страницу 10 приложения D и страницы 313–314 SRD. Сохранённые в реестре наблюдения не дают основания публиковать текст SKT, не устанавливают эквивалентность Monster Manual и не меняют знаменатель.

### Дополнительные действия великанов

На открытой печатной странице 246 есть отдельные заголовки Frost, Hill, Stone и Storm Giants. Под ними описаны соответственно одно, одно, два и одно дополнительных действия для взрослых великанов. Это подтверждает форму четырёх вариантов в приложении C. Их цифровые карточки сохраняются по собственным URL и CR. Совпадение полного содержимого с цифровыми карточками остаётся открытым. Для Fire и Cloud Giant нужны соседние страницы: у первых двух фрагментов на странице 246 отсутствует заголовок родителя. [Официальная страница приложения C](https://media.wizards.com/2016/dnd/downloads/SKT_GiantOptions.pdf).

[Реестр вариантов](../catalog/skt-appendix-c-giant-options-2014.json) связывает все шесть цифровых строк с четырьмя подтверждёнными заголовками и двумя открытыми. Для воспроизведения скачать одностраничный PDF размером 728 068 байт, сверить SHA-256 и проверить заголовки страницы 246. Текст действий и иллюстрация остаются в источнике. Право на публикацию текста и число канонических единиц требуют отдельных решений.

### Hulking Crab и Huge Giant Crab

Издательский индекс показывает обе карточки на одной странице. У Hulking Crab из SKT CR 5 и URL 17349. У Huge Giant Crab из Tales from the Yawning Portal CR 8 и URL 294086. У обеих записей тип Beast и размер Huge. У SKT есть самостоятельный заголовок в приложении C. Для обоих названий в текущем исходном снимке dnd.su совпадений по точному английскому имени нет. [Индекс издателя](https://www.dndbeyond.com/monsters?filter-search=&filter-senses=1&filter-type=0&page=16), [оглавление SKT](https://www.dndbeyond.com/sources/dnd/skt).

[Реестр двух цифровых записей](../catalog/skt-crab-index-comparison-2014.json) хранит SHA-256, URL и различие CR. Ссылки обеих карточек ведут в магазин. Отдельные цифровые локаторы сохранены. Связь печатных версий, права и статус в полном реестре остаются открытыми.

## Отсылки между приключениями в приложении A SKT

На печатной с. 231 открытое приложение A связывает Благофкуса, облачного
великана, с замком Skyreach и призраком его сына Эйгерона. Эррата 2021
заменяет заголовок *Hoard of the Dragon Queen* на *Tyranny of Dragons* и
указывает замену первых трёх абзацев. Имена, замок и отсылка к главе 4
сохраняются. Цифровая эррата ведёт прямо к `#EigeronsGhost`. Это
свидетельство об отсылке сюжета. Игровые параметры NPC определяет его
собственный блок, который по этой ссылке публично не открывается.
[Приложение A, с. 231](https://media.wizards.com/2016/dnd/downloads/EL2_SKT_AppA_0821.pdf#page=1) ·
[Эррата, PDF с. 2](https://media.wizards.com/2021/dnd/downloads/SKT-Errata.pdf#page=2) ·
[Цифровая эррата](https://www.dndbeyond.com/sources/dnd/sae/storm-kings-thunder).

## Оглавления Hoard и Tyranny — 25.11.2026

В открытом цифровом оглавлении *Hoard of the Dragon Queen* приложение B
подписано *Council Scorecard*, раздел *Monsters* — приложение D.
В объединённом *Tyranny of Dragons* тоже указан раздел *Appendix D: Monsters*,
с другим адресом. В объединённом оглавлении есть отдельная ссылка
на Благофкуса. Открытая проверка старого адреса Hoard не вернула
приложение, а именованная ссылка ToD направила в магазин. Буквы
приложений относятся к цифровым оглавлениям. Нумерация печатного Hoard
остаётся на проверке. [Hoard](https://www.dndbeyond.com/sources/dnd/hotdq) ·
[Tyranny](https://www.dndbeyond.com/sources/dnd/tod) ·
[Именной указатель ToD](https://www.dndbeyond.com/sources/tod/monsters#Blagothkus).

В двух открытых дополнениях издателя для Hoard нашли блок *Stone Giant*:
с. 18 PDF из 30 в v1 и с. 17 PDF из 28 в v0.3. Поиск имени Благофкуса
по всем страницам этих файлов не дал совпадений. Дополнения дают
указатель на базового каменного великана, именованный блок остаётся
на сверке. [Дополнение v1](https://media.wizards.com/2014/downloads/dnd/HoardDragonQueen_Supplement1.pdf#page=18) ·
[Дополнение v0.3](https://media.wizards.com/2014/downloads/dnd/HoardDragonQueen_Supplement_v0.3.pdf#page=17).

Вторая страница PDF эрраты SKT v2.0 отмечает поправки на с. 129 и 231
книги. Отсылка теперь ведёт на объединённое приключение, начало
подраздела заменено. Это свидетельство связи сюжетов. Полный статблок,
права и эквивалентность изданий ждут отдельного свидетельства.
У `dndsu:bestiary:3330` и базового SRD Cloud Giant свои указатели.
[Эррата SKT v2.0](https://media.wizards.com/2021/dnd/downloads/SKT-Errata.pdf#page=2).

[Реестр пяти снимков](../catalog/hotdq-monster-locators-2014.json)
сверяется командой `python scripts/audit-hotdq-monster-locators-2014.py <папка-снимков>`.
В Git сохранены версии, размеры, SHA и адреса. Исходные PDF и HTML вне Git.
Для Благофкуса остаётся сверить полные блоки печатного Hoard и объединённого
ToD при доступе к ним. Следующий доступный шаг D06 — проверить
локаторы соседних страниц приложения C для Cloud и Fire Giant.

## Infernal Machine Rebuild и Fiendish Folio

Индекс IMR содержит 56 карточек. У 26 указан IMR, из них у пяти есть наблюдения исходного источника IMR. У 30 карточек указаны другие книги. Boggle и Redcap имеют отдельные цифровые версии. Число 26 на странице издателя относится к доступности в Encounter Builder. Ссылка на приложение B ведёт в магазин при публичной проверке. [Оглавление IMR](https://www.dndbeyond.com/sources/dnd/imr), [страница IMR](https://marketplace.dndbeyond.com/adventures/SRC-00056).

В двух индексах совпадает ровно один URL, Eye of Fear and Flame. Цифровая карточка помечена как IMR, исходное наблюдение остаётся в источнике Folio 206, печатная единица сохранена. Для Folio отдельно учтены 18 строк печатного оглавления, исторические 17 из описания цифрового продукта, 18 карточек текущего фильтра и 17 карточек с подписью Folio. Печатная эквивалентность Eye и причина исторического расхождения остаются без доказательства. [Цифровая карточка](https://www.dndbeyond.com/monsters/581278-eye-of-fear-and-flame), [разъяснение сотрудника издателя](https://www.dndbeyond.com/forums/d-d-beyond-general/release-issues-support/53208-mordenkainens-fiendish-folio-volume-1-bugs-and#c8).

Needlefolk / Needle Spawn остаётся кандидатом. CR 1/2 совпадает, публичная ссылка на карточку перенаправляет к товару. Для решения нужна доступная страница соответствующей версии или прямое подтверждение издателя. [Цифровая карточка Needle Spawn](https://www.dndbeyond.com/monsters/589001-needle-spawn).

## Воспроизведение

- [SKT](../catalog/skt-index-residual-2014.json) собирается командой `node scripts/review-skt-index-residual-2014.mjs`.
- [Отсылки приложения A](../catalog/skt-linked-adventure-boundaries-2014.json) сверяет `python scripts/audit-skt-linked-adventure-boundaries-2014.py <каталог-снимков>`. Извлекаются только метаданные и указатели. Для обновления снимка используется явный `--write` после проверки источников.
- [IMR и Folio](../catalog/imr-folio-index-boundary-2014.json) собирается командой `node scripts/review-imr-folio-index-boundary-2014.mjs`.
- У обоих генераторов `--verify-toc <saved HTML>` проверяет SHA-256 сохранённого оглавления и ожидаемые ссылки. Сырые страницы хранятся отдельно от репозитория.
