# Повышение уровня: экспериментальный контракт

Реализованы транзакция, происхождение, защищённый API и мастер в основной
оболочке под явным флагом. На VPS функция включена 12.11.2026 после проверок. Это не полная
автоматизация всех правил классов.

## Включение и восстановление

Только явный `openStore(filename, {classAdvancement:true})` создаёт три
таблицы схемы версии 1: `class_advancement_schema`, `character_advancement`,
`advancement_changes`. Launcher передаёт параметр только при
`SKAZ_CLASS_ADVANCEMENT=1`; по умолчанию 0, другие значения запрещены.
До включения на живой базе завершить Android-приёмку основной оболочки
и Linux-проверки выпуска. API и совместный перенос уже подключены.
Перед будущим включением нужна полная резервная копия и пробное
восстановление по deployment.md. Откат к старому коду — восстановлением
копии до включения, не удалением отдельных таблиц. Новый код отвергает
неполную/неизвестную схему и базу с происхождением в выключенном режиме.
Более старый код не умеет проверять этот контракт.

## Команды и происхождение

`advanceCharacter` принимает mutationId, expectedRevision, characterId,
classId, fromLevel, hpMethod, hpRoll, choices, reviewedFeatures. Один уровень
за раз, 1–20. Предпросмотр не является разрешением на запись: состояние и
права снова проверяются внутри BEGIN IMMEDIATE. Результат использует
существующие квитанции повторов. Авторизованные обёртки сохраняют проверку
прав, окна и отзыва доступа даже при повторе.

`bindClassResources` принимает те же ID/ревизию, classId, массив bindings
(resourceId/counterId) и create (resourceId). Только до первой истории.
Привязка требует точного максимума и сохраняет остаток; создание нового
счётчика полное и явно подтверждается. Названия не используются для
автоматического присвоения ручных данных. Дальнейшее изменение максимума
сохраняет число потраченных применений; ручная несовместимость блокирует
следующее повышение до будущей процедуры сверки.

Ledger хранит класс 2014, исходный уровень, последовательность уровней,
хэши команд, страницы SRD, подтверждённые названия умений, происхождение
счётчиков и выбранных заклинаний. Это не полный журнал эффектов умений:
сами эффекты ещё ручные, подтверждение означает только проверку правил.
ASI/хиты/лист дополнительно имеют существующий транзакционный аудит.
Не поддержаны черты, подклассы, экспертиза, метамагия и другие обязательные
выборы без реализации. Они закрывают путь записи, а не молча пропускаются.

## Перенос

Внутренний exportActive(13) включает обязательное поле advancement (null
или проверенный ledger). Импорт проверяет уровень, счётчики, доступность
и количество выбранных заклинаний. Новая игра получает новые IDs героя;
происхождение сохраняется, прежние уровни повторно не исполняются.
Для героя с ledger старый экспорт v2–v12 запрещён. При включённом флаге
основная оболочка экспортирует v13. Пакет игры с личными изображениями
v2 содержит игру v13; старый пакет v1 содержит v12. Смешанные пары
отвергаются. Импорт истории, PNG, прав и игры выполняется одной транзакцией;
поздняя ошибка изображения откатывает и происхождение. Точный повтор
после потери ответа не создаёт вторую игру.

## API и основная оболочка — 11.11.2026

`/api/class-advancement/classes` и `/plan?classId=...` читают только
выбранного доступного героя. POST `/preview`, `/apply`, `/bind` сохраняют
проверки Origin, сессии, окна, права записи и заголовка клиента. При
выключенном флаге маршруты и `/api/export/active-v13` отвечают 404.
Класс выбирается явно; после привязки происхождения смена запрещена.
Предпросмотр ничего не пишет, подтверждение заново проверяет всё в store.

Клиент проверяет героя, ревизию и запись mutationId в происхождении ответа.
Повтор хранит прежнюю команду только в памяти. Закрытие, смена героя и
выход освобождают запросы/форму; незавершённая операция требует явного
выбора выхода. После закрытия с попыткой записи лист перечитывается,
поскольку операция могла сохраниться; сама команда не отправляется снова.

`node scripts/class-advancement-app-fixture.mjs 4245 --lose-response` —
основная оболочка на RAM-базе, намеренно повреждает один успешный ответ.
`node scripts/game-art-transfer-fixture.mjs 4246 --advancement` — совместный
пакет v2. Ни один стенд не открывает пользовательские кампании.
Дополнительные тесты: class-advancement-http, class-advancement-transport,
class-advancement-shell, game-art-transfer-client, personal-art-game-transfer.

## Репетиция выпуска и резервирование

`node scripts/verify-advancement-migration.mjs <стабильная-копия.sqlite> <новый-файл.sqlite>`
создаёт отдельную копию, включает схему только в ней и сверяет содержимое
и определения всех прежних таблиц. Проверяет integrity/FK и разрешает
только три новые таблицы повышения. Существующий путь назначения не
перезаписывается; данные и хэши строк не выводятся. При изменении исходника
во время копирования репетиция завершается ошибкой: использовать стабильный
backup, а не активно изменяемую базу. Репетиция не является включением функции.

Ежедневный `scripts/backup.mjs` использует read-only SQLite backup без
openStore: резервирование не зависит от флага повышения и не запускает
миграций. Проверено восстановление истории и точной квитанции повтора.
После будущего включения защищённый проверяющий скрипт запускается с
`verify-individual-deployment.mjs <HTTPS-origin> <приватный-JSON> <минимум> --advancement`.
Он сверяет v13 и происхождение с доступным листом, проверяет доступ к классам
и отзывает собственный проверочный сеанс даже при расхождении. Без флага
он по-прежнему проверяет действующий v12. Игровых записей не создаёт.

Это не миграция живой базы. Откат после первого такого выбора требует
совместимой версии приложения либо восстановления копии до обновления;
нельзя удалять styles или понижать version ради запуска старого кода.

## Метамагия и совместимость — невыпущенный кандидат 14.11.2026

Восемь вариантов SRD2014 имеют устойчивые ID и отдельные описания. На уровне3
обязательны два разных варианта, на10 и17 — ещё по одному. Прежние варианты
исключены из выбора. Если герой начал вести историю позже и прежний выбор
неизвестен, повышение на10/17 блокируется с объяснением; старые данные не
угадываются и не мигрируют. Применимость к заклинанию и расход единиц ручные.

Первое получение Метамагии создаёт ledger v3 с обязательными styles (может
быть пустым) и metamagic. Каждый вариант хранит ID, класс, уровень, choiceId,
редакцию и страницу. Полная цепочка2→17 проверена: варианты3/3/10/17,
точные повторы, запрет дублей и сохранение потраченных единиц при росте
максимума. v14 переносит эту историю; HTTP и компонент формы проверены.

Маркеры SQLite и вложенные версии ledger — разные величины. Новая база
по-прежнему начинает с class_advancement_schema.version=1. При первой
записи ledger v2 или v3 (включая импорт) маркер меняется на2 В ТОЙ ЖЕ
транзакции. Прежний код понимает только маркер1 и отказывает до миграций.
Новый код читает оба маркера, проверяет все текущие истории, включая
неактивных героев, до изменения базы и отвергает несоответствие маркера.
Поздняя ошибка записи откатывает и историю, и маркер. Не понижать его вручную.

Восстановлены синтетические SQLite-копии до/после обоих новых выборов,
сверены данные, integrity_check, FK и повтор исходной команды без удвоения.
Это локальная репетиция; резерв/восстановление VPS этим не подменяются.
