# Prisoner13: компонент антологии и отдельная выдача — #77 D05

21.11.2026. [Свидетельство](../catalog/prisoner13-publication-component-2014.json) проверяет provider105 из [исторического остатка15](library-publication-context-review-2014.md). Это проверка reference-отношения, не перенос полной игры/правил.

## Первичные основания

- [Статья DND Staff](https://www.dndbeyond.com/posts/1438-claim-your-copy-of-prisoner-13-and-infiltrate) в собственном articleBody прямо относит приключение к антологии Keys from the Golden Vault и содержит ссылку на неё. Анализируются текстовый факт/ссылка и SHA абзаца; комментарии/навигация исключены, сам текст не копируется.
- [Оглавление антологии](https://www.dndbeyond.com/sources/dnd/kftgv) содержит отдельный заголовок приключения и отдельно одноимённый статблок существа. В JSON сохранены разные URL главы и fragment-ссылки. Приключение не становится существом или алиасом по названию.
- Анонимный GET [отдельного источника](https://www.dndbeyond.com/sources/dnd/p13) перенаправился на публичную claim-страницу. Это не прочитанное полное приключение. Claim не отправлялся, вход/куки не использовались; обхода доступа нет. Бесплатное предложение выдачи не является разрешением переиздавать/переводить полный текст. Публичные providerIsFree=false сохранены как наблюдения, не «исправлены» по рекламной фразе.

Три HTTP200 снимка: статья362872байта/SHA77dbe0a1…, оглавление258131/c1088c61…, claim-landing221329/9ddf70b7…. Полные SHA/URL/редирект/время в JSON; HTML/полные тексты/аккаунтные сведения не включены вGit.

## Что связывается

Provider105/Prisoner13 — отдельная distribution-запись для приключения-компонента provider103/Keys. Уже существующая historical-связь антологии — dnd.su189; она проверена по актуальному промежуточному отчёту. Provider105 не соединяется с dnd.su105 по числу, childDndsuSourceId=null. Автоматической атрибуции наблюдений/замены sourceIds нет.

Полное текстовое равенство standalone-выдачи и главы, версия, дополнительные/изменённые записи, каноническая гранулярность и reusePermission остаются unverified/not-established. Исторический15-остаток не переписан и не объявляется перечнем15пропущенных книг. Это одно проверенное отношение компонентов, не новый знаменатель.

## Проверка и передача

```sh
python scripts/audit-prisoner13-component-2014.py <capture-folder> --output <report.json>
python -m unittest discover -s tests -p test_prisoner13_component_2014.py
```

Папка содержит article.html, parent.html, child.html, capture.json. До парсинга закреплены requested/final URL, status, bytes, SHA.10Python проверяют границу articleBody, ложную ссылку, повторный контейнер, одноимённый статблок без adventure-заголовка, fragment вместоглавы и редирект без ложного доступа. Реальный отчёт воспроизведён; independent read-only ревью отдельно доmerge.

Следующий полезный content-шаг — точная версия/выбранное общее правило в BasicRules/SRD либо другой тип связи из15; отсутствие child fulltext ограничивает только сравнение отдельной выдачи, не независимую очередь. Runtime/UI/Android/VPS/профили не менялись, M0/этапы открыты.

Рефлексия content: первичная статья плюс TOC отделили компонент от отдельной выдачи; одно название одновременно обозначает приключение и creature. Предложение планировщику — всегда сохранять kind и локатор заголовка/фрагмента до alias/merge; польза — нет ложного слияния, затраты — две ограниченные проверки, риск версии/полного текста остаётся явным.
