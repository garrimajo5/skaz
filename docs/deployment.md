# Размещение СКАЗ на закрытом VPS

Состояние на 20.10.2026: приложение доступно по HTTPS на VPS владельца. Это закрытая версия с общим входом через Nginx, не многопользовательский сервис с ролями. Node слушает только 127.0.0.1:4173. Вкладки независимо выбирают кампанию и персонажа; общая ревизия защищает от перезаписи чужого прогресса. Выбор не является разграничением доступа: общий пароль пока позволяет открыть любого героя. Локальные кампании автоматически не загружаются на VPS.

## Устройство

- Ubuntu 24.04, Node.js 24; внешних npm-зависимостей нет.
- `/opt/skaz/releases/<release>` — исходники конкретного релиза, root-owned; `/opt/skaz/current` — активный релиз.
- `/opt/skaz-node` — проверенная по SHA256 официальная сборка Node 24.
- `/etc/skaz.env` — PORT, SKAZ_DB, SKAZ_PUBLIC_ORIGIN. Шаблон: `deploy/skaz.env.example`.
- `/var/lib/skaz/skaz.sqlite` — рабочая база, отдельный непривилегированный пользователь skaz. Каталог из встроенной подборки установлен; реальных локальных игр здесь нет.
- `/etc/nginx/skaz.htpasswd` — хеш отдельного пароля приложения; root-пароль не используется для входа в СКАЗ. Все страницы и API закрыты Basic Auth через HTTPS. Исключение — только публичная ACME-проверка сертификата.
- `/etc/letsencrypt/live/skaz-ip/` — доверенный сертификат IP, ключ не входит в репозиторий. Certbot находится в `/opt/skaz-certbot`.
- Сетевой экран допускает SSH, HTTP для перенаправления/ACME и HTTPS. Порт приложения наружу не открыт.

Шаблоны systemd и Nginx находятся в `deploy/`. В nginx/env замени `__PUBLIC_HOST__` точным IP или доменом. `PUBLIC_ORIGIN` разрешает источник запросов, но сам не защищает вход: обязательны TLS и проверка пароля на прокси. Не разрешай вход к Node напрямую и не доверяй произвольным X-Forwarded-*.

## Эксплуатация

```sh
systemctl status skaz
journalctl -u skaz -n 50 --no-pager
systemctl list-timers --all
systemctl start skaz-backup.service
```

`skaz.service` включён при загрузке, перезапускается после ошибки, работает без root и имеет ограничение памяти 1 ГБ. Доступ на запись — только к базе и приватному временному каталогу. Стандартный запуск локально остаётся прежним и не требует публичного origin.

`skaz-backup.timer` делает согласованную SQLite-копию ежедневно около 03:15 UTC. Копии сохраняются в `/var/backups/skaz`, доступны пользователю skaz и root. Это резерв на том же VPS: он защищает от ошибочного изменения, но не от потери всего сервера. Отдельное внешнее хранилище пока не настроено; автоматическое удаление старых копий не включено.

IP-сертификаты Let’s Encrypt короткоживущие. `skaz-certificate.timer` проверяет продление каждые шесть часов с разбросом до 30 минут; успешное продление перезагружает Nginx. Проверка: `/opt/skaz-certbot/bin/certbot renew --dry-run --run-deploy-hooks`. Источник: https://letsencrypt.org/2026/03/11/shorter-certs-certbot . Обновления пакетов ОС и Node контролируются отдельно; автоматический переход на новый major Node не настроен.

## Обновление

1. Прочитай git status и план. Сохрани пользовательские изменения. Прогони нужные тесты, синтаксис и сборку; закоммить проверенные исходники.
2. Передай только исходники, каталог, тесты и конфигурационные шаблоны в новый каталог релиза. Не передавай локальные `data/`, SQLite, аудио, резервные копии и файлы доступа. Привяжи релиз к SHA коммита.
3. Прогони Node-тесты и сборку на Linux в новом каталоге. Не тестируй мутации на рабочей базе.
4. Создай backup действующей версией. Сохрани путь текущего релиза и копии. Переключи `/opt/skaz/current`, перезапусти skaz, проверь health, закрытый вход, Origin и доступ с верным паролем.
5. При несовместимой миграции откат кода не достаточен: останови сервис, выбери сохранённую копию БД отдельным файлом через SKAZ_DB, верни прежний релиз, запусти и проверь. Не заменяй файл работающей SQLite и не уничтожай более новый прогресс.

Для смены пароля приложения: `htpasswd /etc/nginx/skaz.htpasswd skaz`, ввод интерактивный. Не помещай пароль в команды shell, Git или журналы.

20.10.2026 владелец отдельно разрешил постоянный SSH-ключ без парольной фразы для обновлений этого VPS. Ключ создан локально: `C:/Users/FEDYA/.ssh/skaz_vps_ed25519`, публичная часть — соседний `.pub`. Отпечаток: `SHA256:/lUYvHXJn3/u8jeRCwhn/xrr6MewZlhKqD6mnzhDIHo`. Закрытый ключ находится вне репозитория; не копировать его в проект, журналы или автоматизацию. На VPS добавлена только публичная часть, с запретом перенаправления портов, агента и X11; прежние записи authorized_keys сохранены. Существующий вход администратора не отключён.

Подключение для обслуживания:

```powershell
ssh -i C:/Users/FEDYA/.ssh/skaz_vps_ed25519 -o IdentitiesOnly=yes -o BatchMode=yes root@2.56.179.225
```

Отдельное подключение без пароля проверено: пользователь root, сервис skaz active, health возвращает status=ok. Это согласие касается SSH-ключа; полного обновления ОС оно не разрешает.

## Что ещё не реализовано

Индивидуальные аккаунты, разделение прав мастера и игроков, внешние резервные копии, распознавание речи и оплачиваемые AI-вызовы. Пользовательский лист всё ещё начинается с демо-шаблона; наличие каталога не означает полноту всех материалов D&D.

Проверенный релиз кода первого развёртывания: `14745ae`. На Windows и Linux прошли282 Node-теста и сборка; внешний smoke-check подтвердил401 без входа, доверенный сертификат IP, авторизованный API и защиту Origin. Пробное продление сертификата и восстановление SQLite в отдельный файл прошли. Кратковременное отсутствие сокета сразу после restart учитывается проверкой health с retry. Полное обновление ОС не выполнено: отдельный шаг после решения владельца, автоматическая проверка отклонила широкое apt upgrade.


## Внешняя проверка после обновления

`node scripts/verify-deployment.mjs https://2.56.179.225 путь-к-приватному-json 460` проверяет только чтением: 401 для страницы/прогресса/каталога/экспорта без входа и неверного пароля, готовность авторизованного API, минимальное количество материалов, запрет постороннего Origin и точное HTTP→HTTPS перенаправление. JSON с полями username/password хранится вне Git (например, в игнорируемом data/), содержит отдельный пароль приложения. Не передавай пароль аргументом командной строки. Проверка не следует перенаправлениям с авторизацией, не выводит ответы/секреты и не допускает отключённую проверку TLS. Скрипт не заменяет тесты логики, backup и проверку восстановления.
