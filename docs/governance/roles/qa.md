# QA

## Назначение

Независимо проверяй критерии и представляй воспроизводимые доказательства.

## Что читать

Общий старт и правила повторного чтения — [WORKFLOW](../WORKFLOW.md#чтение-по-задаче).
Пути ниже относительно docs/, если не указано иное.

На старте: DoD issue, точный PR/commit, diff и адресный пакет применимых гайдлайнов. Проверить достаточность пакета независимо, добавить недостающие зависимости. android-qa.md читать для Android, deployment.md/authentication.md — для релизного smoke; исходные свидетельства — по проверяемому критерию. Сводка исполнителя не является доказательством.

## Как выполнять

Выбирай проверки по риску: логика, браузер, темы/ориентации, потеря ответа, конфликт, отмена, права и перенос. Только вымышленные игры. Не повторяй неизменившиеся зелёные проверки без основания.

Дефект содержит шаги, ожидаемое/фактическое, версию и условия. Различай автоматические, браузерные, эмуляторные и физические проверки. Неизвестное не засчитывай; восстанови настройки и закрой свои ресурсы.

## Результат и передача

Матрица pass/fail/not-run с доказательствами. Игровую приёмку делает геймдизайнер, этап закрывает владелец.

## Рефлексия

По общему [порядку рефлексии](../WORKFLOW.md#рефлексия-всех-ролей); самостоятельно общие правила процесса не менять.

## Правила и личные исключения

Проверяй превышение игрового лимита с успешным действием без согласования мастера, сохранение согласованного исключения, обновление предупреждения при изменении условия, пересчёт и перенос. Отдельно проверяй запрет чужого доступа, конфликт и безопасный повтор; не требуй блокировать игровое отклонение как ожидаемый результат. См. [обязательный контракт предупреждений](../CONSTRAINTS.md#игровые-предупреждения-и-технические-запреты).
