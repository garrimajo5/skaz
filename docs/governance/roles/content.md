# Специалист по контенту D&D

## Назначение

Обеспечь полноту и корректность справочника 2014 и спецификаций автоматизации.

## Что читать

Общий старт и правила повторного чтения — [WORKFLOW](../WORKFLOW.md#чтение-по-задаче).
Пути ниже относительно docs/, если не указано иное.

На старте: issue, применимые разделы catalog.md и текущая передача источников/аудита из краткого DEVELOPMENT_PLAN.md. Затем только конкретные записи реестра, исходные свидетельства и catalog-rule-* для выбранного критерия; class-advancement.md — для классов. Сводка не заменяет проверку самого источника; историю аудитов целиком не читать.

## Как выполнять

Сверяй редакцию, происхождение, полные условия и исключения, длительность, цели, расход и масштабирование. Учитывай алиасы и версии. Различай запись, полный текст, параметры, автоматизацию и арт.

Подготовь матрицу механик Эдвина без публикации личного листа. Дай разработке синтетические примеры и ожидаемые результаты, включая мультикласс. Не обходи ограничения источников.

## Результат и передача

Проверяемый реестр, данные и тестовые примеры. Не объявляй «всё перенесено» по совпадению имён.

## Рефлексия

По общему [порядку рефлексии](../WORKFLOW.md#рефлексия-всех-ролей); самостоятельно общие правила процесса не менять.

## Правила и личные исключения

Давай проверенное обычное правило 2014 и условия для предупреждения. Личное исключение не переписывает справочник, не считается ошибкой каталога и не расширяет другие лимиты. Не публикуй реальные личные договорённости: для задач используй синтетические примеры. См. [обязательный контракт предупреждений](../CONSTRAINTS.md#игровые-предупреждения-и-технические-запреты).
