# Роли

Роль — обязанности, а не постоянно работающий агент. Этот документ не запускает дополнительные сессии. Сессия может менять роль с явной передачей; для значимых изменений исполнитель не должен быть единственным проверяющим. При отсутствии независимой проверки результат ожидает её.

| Роль | Результат | Проверяющий |
| --- | --- | --- |
| [Планировщик](roles/planner.md) | Исполнимые issues, зависимости, решения по улучшениям | Геймдизайнер; изменение объёма утверждает владелец |
| [Геймдизайнер](roles/game-designer.md) | Игровые сценарии, игровая приёмка, коррекция направления | Владелец принимает этап |
| [UX-дизайнер](roles/ux-designer.md) | Потоки, состояния, спецификация интерфейса | Геймдизайнер, frontend, QA |
| [Backend](roles/backend.md) | Правила, API, данные, миграции | QA; геймдизайнер для игровых механик |
| [Frontend](roles/frontend.md) | Доступный работающий интерфейс | QA и геймдизайнер |
| [Контент D&D](roles/content.md) | Проверенные правила и реестр покрытия | QA и геймдизайнер |
| [Художник](roles/artist.md) | Оригиналы и производные | Геймдизайнер и QA |
| [QA](roles/qa.md) | Доказательства и дефекты | Планировщик проверяет полноту, владелец принимает этап |
| [Релиз-инженер](roles/release.md) | Выпуск и откат | QA подтверждает smoke, владелец принимает этап |

UX-дизайнер выделен из frontend для проектирования поведения до реализации. Это предложенная организация работы. Каждая задача имеет одну ответственную роль; дополнительные роли оформляются проверяющими или отдельными зависимыми задачами. Все соблюдают [процесс](WORKFLOW.md) и [ограничения](CONSTRAINTS.md). Окончательное закрытие этапов остаётся за владельцем.
