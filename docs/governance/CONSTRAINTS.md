# Ограничения и гайдлайны

## Общие

- D&D 5e 2014, без хомбрю и 2024.
- Сохранять пользовательские изменения, кампании, исходники и устойчивые ID. Реальный Эдвин не используется как QA-фикстура: разработка проверяется на вымышленных эквивалентах, свою игровую сессию оценивает владелец.
- Не коммитить и не публиковать пароли, ключи, SQLite, резервные копии, аудио и личные листы.
- Эти документы не разрешают микрофон, платные AI API и подагентов. Для артов — только разрешённый встроенный генератор.
- Своя ветка/worktree; не переключать чужой checkout, не останавливать чужой стенд и не запускать параллельный блок той же задачи.
- Локальный браузерный стенд: согласованный 127.0.0.1:4337. Проверять владельца процесса перед использованием. Срочные разрешения проверять по области и сроку; документ их не продлевает. Новые внешние порты не разрешены автоматически.
- ADB разрешён для QA СКАЗ: вымышленная игра, окно :25–:55 МСК и проверка фактической занятости Pixel_8. После работы восстановить исходные настройки, закрыть свои вкладки/пробросы. Чужой прогон не трогать.

## Технические

Текущий стек: Node.js 24+, JavaScript, HTTP API, SQLite. Смена стека и новые сервисы не вводятся побочно. PostgreSQL в старом концепте — историческое предложение, не требование миграции.

Сервер проверяет права, данные и целевой контекст. Мутации атомарны, защищены от повтора и конфликта; автоматические значения имеют происхождение. Миграции/перенос сохраняют совместимость и проверяются на копии. Обязательный интернет не отменяет обработку потери ответа.

Контракты: [API](../local-api.md), [сущности](../entities.md), [повышение](../class-advancement.md), [сотворение](../casting-operation.md), [доступ](../access-control.md).

Выпуск по [deployment](../deployment.md): резерв, проверенное восстановление, совместимый откат, защищённый smoke. HTTPS и вход не ослаблять; локальные кампании на VPS не переносить. Слияние кода не означает разрешение включить непроверенный флаг.

## UX и визуальный язык

Полярис, Уголь, Атлас; быстрые действия в Игре, подробная настройка в Подготовке. Не терять фокус и контекст без причины. Обязательны понятные состояния ожидания, ошибки, конфликта, пустого результата и недоступного действия. Цвет не единственный носитель смысла.

Применять [визуальные гайдлайны](../design/visual-guidelines.md), [темы](../design/themes.md), [библиотеку артов](../design/visual-library-plan.md). Проверять фактический контраст и сенсорные цели. Телефон и планшет — по [Android QA](../android-qa.md); эмуляция не доказывает физический Safari/iPad или длительную игру.

## Контент и арт

Фиксировать источник, редакцию, версию и ID. Раздельно учитывать наличие записи, полный текст, корректность параметров, автоматизацию и иллюстрацию. Условия использования источников проверяются до включения материалов. Заглушки не считаются покрытием.

Сохранять оригиналы, промпты, SHA, derivedFrom, PNG и миниатюры по существующему реестру. Проверять узнаваемость, перспективу, число элементов и соответствие механике. Библиотечные арты и четыре состояния портрета — разные задачи.

## Какие документы включать в issue

| Тип | Обязательные профильные документы |
| --- | --- |
| Backend | Технические ограничения, затронутые API/сущности/правила/доступ |
| Frontend/UX | UX и визуальные гайдлайны, темы, соответствующий API, матрица экранов |
| Контент | catalog.md, реестр источников и аудиты правил |
| Арт | visual-guidelines, visual-library-plan, карточка механики, арт-реестр |
| QA | Все применимые документы проверяемой задачи, android-qa при Android |
| Выпуск | deployment, authentication, критерии выпуска PR |

Каждый issue дополнительно ссылается на цель и инструкцию роли. Неприменимость критерия обосновывается. Противоречие с историческим документом фиксирует планировщик; цели и требования безопасности не отменяются молча.
