# Индивидуальный вход: экспериментальный адаптер

Состояние 20.10.2026: серверные сессии и экран входа реализованы и покрыты тестами, но `server/index.mjs` пока не включает этот режим. На VPS действует общий вход Nginx. Самостоятельной регистрации, восстановления пароля и UI назначения участников пока нет. Не снимать общий вход до совместной HTTPS-проверки отдельных пользователей, отсутствия назначений, смены аккаунта и восстановления backup.

## Сервер

Доверенная сборка вызывает `createApp(store, {publicOrigin, sessions: store.authentication(), individualWrites: true})`. HTTPS origin обязателен. По умолчанию запись индивидуального адаптера выключена. Пользователей и разрешения создаёт только администратор по процедуре access-control.md; пароль не создаёт пользователя и не присваивает ему существующую игру. Схема auth создаётся лениво: общий режим не создаёт таблицы сессий.

Пароли 15–128 Unicode-символов, не более 512 байт UTF-8; пробелы не удаляются. Scrypt N=131072, r=8, p=1, случайная соль 16 байт, ключ 32 байта. Одновременно не более двух вычислений (избыточное получает 503). Ограничение попыток хранится в SQLite: 5 за 15 минут на логин, 20 в минуту суммарно, включая успешные входы. Неизвестный логин и неверный пароль имеют одинаковую ошибку и вычисление. Это защита небольшой закрытой группы; глобальный лимит может временно ограничить остальных пользователей при злоупотреблении.

Случайный токен 32 байта передаётся только cookie `__Host-skaz-session`: Secure, HttpOnly, SameSite=Strict, Path=/, без Domain. В SQLite хранится SHA256 токена. Срок 12 часов абсолютный, 2 часа бездействия; не более 10 сеансов пользователя. Вход меняет токен, выход отзывает текущий. Смена пароля, отзыв всех сеансов и отключение пользователя делают старые сеансы недействительными, включая незавершённую проверку пароля. Повторная проверка прав/сеанса внутри транзакции не позволяет завершить отозванное сохранение с задержанным телом запроса.

POST `/api/auth/login` принимает ровно login/password, POST `/api/auth/logout` — пустой объект. JSON ограничен 8192 байтами. Требуются точный Origin и X-Skaz-Client. Токен не возвращается JSON и не хранится в localStorage. API индивидуального режима дополнительно требует X-Skaz-Identity, совпадающий с проверенным сеансом; этот заголовок только ограничивает запрос, не удостоверяет личность.

## Браузер

HTML без сеанса содержит форму входа; HTML после проверки получает ID пользователя от сервера. account.js закрепляет этот ID во всех API-запросах. При 401, смене входа в соседнем окне или возврате страницы из back-forward cache старый интерфейс скрывается, новые команды блокируются. Ответ в полёте после блокировки не передаётся приложению.

Очередь изменений и формы событий используют префикс пользователя; старые общие черновики не переносятся автоматически. В настройках перечисляются только черновики текущего пользователя. Это предотвращает случайное смешивание данных, но не шифрует localStorage и не защищает от человека с доступом к профилю браузера/инструментам разработчика. На общем устройстве для недоверяющих друг другу людей нужны отдельные профили браузера.

## Администрирование и восстановление

`node scripts/auth-admin.mjs база.sqlite приватная-команда.json новая-копия.sqlite`

Команда set-password содержит action, userId, login, password; revoke-sessions содержит action, userId. JSON хранить вне Git, доступ только администратору (0600 на Linux), пароль не передавать аргументом командной строки. Перед изменением создаётся новая приватная SQLite-копия; существующая копия не перезаписывается. Вывод не содержит пароль. Удаление приватного файла после использования — обязанность администратора.

Backup включает хеши и сеансы. При восстановлении старой копии ранее отозванные сеансы могут вернуться: до открытия доступа отозвать сеансы всех пользователей в восстановленной базе. Не заменять открытый SQLite-файл. Режим общий/индивидуальный и конфигурацию прокси менять только согласованно, сохраняя HTTPS и проверенный путь возврата.

## Основания и проверки

Параметры сверены с [Node.js crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html), [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) и [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html). Это не независимый аудит безопасности.

Тесты проверяют реальные SQLite-сеансы, гонки сброса/отзыва, HTTP Origin/cookie/идентичность, ограничение устройств и вычислений, клиентскую очередь разных пользователей и поздние ответы. В браузере проверены экран входа и три темы при фактическом настольном размере; полный вход через настоящий HTTPS браузера и физический планшет ещё не засчитаны. Экран без назначенного героя реализован: повторная проверка доступа и выход, без загрузки общего листа. Права в UI реализованы: роль, доступные действия, личные записи игрока, блокировка общих изменений и режим чтения. Следующий этап — интерфейс участников и полноценный браузерный HTTPS-сценарий перед включением на VPS.
