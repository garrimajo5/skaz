## Очередь и критерии готовности

Завершён 19.10 интерфейс сессий: кнопка «Сессии», обязательные название/дата, начало через очередь повторов, список и архив только для чтения. Заголовки используют реальные метаданные; вымышленные записи удалены из журнала и экспорта. Личные заметки сохраняются между сессиями и явно обозначены. Рабочая сессия пользователя не менялась; браузерная проверка в отдельной базе.

Завершён 19.10 серверный этап сессий: явные название/дата, новая сессия в активной кампании без сброса ресурсов, архив предыдущего журнала только для чтения. Повторы/ревизии/история работают в общей транзакции. Старые даты не выдумываются. Интерфейс подключён следующим завершённым этапом.

Завершён 19.10 интерфейс кампаний: список, создание из явно обозначенного демо-шаблона, переключение. Незавершённые команды сохраняются в браузере и повторяются с исходным ключом после перезагрузки; при черновике переключение блокируется. Отмена прежней игры сбрасывается. Тестовые кампании созданы только в отдельной игнорируемой базе.

Завершён 19.10 серверный этап: GET /api/campaigns, POST /api/campaigns и POST /api/context/select. Создание требует явного полного состояния и активирует новую игру. Команды атомарны, защищены общей ревизией и ключами повторов; квитанции сохраняют ID затронутой игры. Интерфейс подключён следующим завершённым этапом.

1. Выполнено: подключить серверный каталог к библиотеке. Браузерная проверка в узком (580 px) и широком (1265 px) окне; все три темы в узком окне. Реальный планшет остаётся в пункте 7.
2. Кампании, персонажи и сессии: хранение, ID, миграция, API и интерфейс кампаний/сессий выполнены. Создание дополнительных персонажей ещё требуется. Модель остаётся локальной, без пользователей и прав доступа; новые кампании явно используют демонстрационный шаблон.
3. Структурированные данные 2014: отдельные проверяемые схемы механик/заклинаний/монстров/предметов/артефактов; лицензированный источник, атрибуция, числовые поля, связи, отчёт покрытия и повторяемый импорт. Никакого заявления о полноте без сверки.
4. Привязка каталога к листу/инвентарю: добавление, расход ресурсов, отмена, проверка повторов; регрессии и браузерная проверка.

7. Доступ с настоящего планшета: безопасная локальная настройка доступа, проверка шестичасового сценария; хостинг после решения пользователя, ориентиры в hosting.md.
