Следующий шаг: привязка заклинаний каталога к персонажу (серверная модель изученных/подготовленных заклинаний, не зависящая от восьми демо-примеров), затем интерфейс и перенос этих связей. Применение эффектов предметов, редактируемые задания/карта и остальные пункты очереди сохраняются.


## Этап 19.10: серверный список заклинаний персонажа

Правила класса, лимиты подготовки, расход ячеек и эффекты не автоматизированы. Клиент не менялся, реальные данные не менялись.

## Этап 19.10: перенос заклинаний v3

Выполнено: серверный экспорт v3 включает ручные отметки заклинаний и их источники/зависимости вместе с инвентарём. Импорт v3 создаёт новую игру атомарно со списком заклинаний и историей. V2 совместим, его нормализованные ключи повторов сохранены; экспорт v2 при непустом списке заклинаний возвращает понятный отказ вместо тихой потери данных. Клиент пока остаётся v2.

Проверки: 72 теста Node, синтаксис и сборка. Перенос prepared/known и источника, повтор, неверный статус, пропущенный список, дубли/неизвестный ID, rollback записей и истории при сбое, HTTP v3, старые регрессии v2. Клиент не менялся; браузерная проверка не требовалась. Реальные данные не менялись.

Следующий шаг: клиентский список заклинаний из каталога и настройки переноса v3, с явными границами ручных отметок и отсутствия автоматической проверки класса; регрессии очереди и браузерная проверка. Остальные задачи сохраняются.


## Этап 19.10: настройки переноса v3

Выполнено: клиент экспортирует v3 с предметами и заклинаниями, принимает v1/v2/v3, показывает количество заклинаний в предпросмотре и отсутствие списка у старого v2. Отсутствующий список v3 отклоняется до подтверждения. Старые сценарии импорта сохранены.

Проверки: 74 теста Node, синтаксис и сборка. Новые регрессии: v3 передаётся с неизменным списком, предварительный просмотр не выполняет запись, отсутствие списка отклоняется, экспорт обращается к v3 и отклоняет другую ревизию. Браузер: выбор тестового v3 с одним подготовленным заклинанием и двумя зельями, предпросмотр, успешная новая кампания; затем чтение тестовой базы подтвердило список. Снимок docs/design/transfer-v3-preview.png. Реальные данные не менялись.

Следующий шаг: клиентский список заклинаний из каталога и ручные отметки изучено/подготовлено/убрать, с регрессиями очереди и браузерной проверкой. Остальные задачи сохраняются.

## Этап 19.10: серверный перенос заданий v4

Повторный перенос и редактирование сохраняют первоначальное происхождение. Старая игра остаётся доступной.
