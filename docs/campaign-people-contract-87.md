## Сущности и поведение

| Запись | Минимальные поля и правила |
| --- | --- |
| Лицо кампании | Стабильный ID, ID кампании, имя или наблюдаемое прозвище, краткое описание и отдельное необязательное отношение. Совпадающие имена сверяются вручную. Карточка не создаёт игровой лист или запись бестиария |
| Сведение | ID, ID лица, `known` или `assumption`, текст и источник. Исправление адресное и записывает предыдущую версию. Подтверждение предположения как известного — отдельное явное решение с сохранением происхождения |
| Встреча | ID, ID лица, необязательные связи с местом и сессией. Текст, сохранённый игроком, можно читать при недоступной связи. Неуказанные место и сессия представляются независимо |
| Последнее наблюдение | Ссылка на встречу этого лица. Историческую встречу можно добавить без смены последней. Когда порядок неоднозначен, последнее наблюдение выбирается явно. Время записи или исправления не определяет игровую хронологию |
| Связь с дневником | Стабильная ссылка доступна на сессию. Пока отдельная заметка не имеет ID, можно сохранить её текстовое уточнение с происхождением. Индекс массива, время и заголовок не используются как адрес заметки |

## Предложение для API и прав

Чтение — список и карточка известного лица в активной кампании. Карточка возвращает сведения, встречи, связанные записи и статус доступности каждой ссылки. Место, сессия, задание и лицо разрешаются только по паре ID и кампании. Источник из переноса показывается простым текстом до разрешения связи. Скрытые данные мастера, чужих героев и бестиария из связей не извлекаются.

Запись — одна команда с `mutationId, expectedRevision, campaignId` и строгим payload выбранного действия. Роли записи совпадают с текущими общими местами и заданиями. Редактор доступов остаётся авторитетным. Запись, история и квитанция меняются одной транзакцией после проверки всех связанных ID. Точный повтор при сохранившихся правах возвращает прежний результат и его контекст. Смена тела или ревизии даёт конфликт, недоступный ID не раскрывает существование, отзыв прав действует и на повтор. [Действующий доступ](access-control.md) · [Локальный API](local-api.md)

## Перенос и проверка

Текущий v15 не представляет картотеку и архивные сессии. При реализации нужен формат, который умеет сохранять карточки, историю и связь со всеми включёнными целями. Старый путь экспорта должен явно сообщать, что такой формат нужен, если в игре уже есть записи картотеки. Режим совместимости v15 и путь отката требуют отдельной репетиции до записи новых данных.

Импорт создаёт соответствия старых и новых ID для каждого типа внутри новой кампании. Ссылки на включённые цели восстанавливаются по этим соответствиям. Ссылка с отсутствующей включённой целью является ошибкой пакета. Явно невключённая историческая цель сохраняет текст и происхождение и остаётся без активной ссылки. Сырой старый ID никогда не ищется в другой кампании.

| Проверка для реализации | Ожидаемый результат |
| --- | --- |
| Две кампании, одинаковые имена и заголовки, попытка связать чужой ID | Отдельные карточки. Чужой ID не изменил записи и не раскрыл сведения |
| Добавить встречу задним числом, затем исправить её и явно выбрать последней | Прежняя история читается. Решение меняется только при явном выборе |
| Поправить предположение, затем подтвердить его как известное | Исправление сохраняет тип. Явное подтверждение оставляет исходный тип и источник в истории |
| Потерять ответ, повторить, поменять тело или отозвать право | Одна запись и одна история. Конфликт или отказ не содержит чужого результата |
| Экспорт и импорт с включённой сессией и невключённым архивом | Первая связь получает новый ID. Архивное происхождение читается, фиктивная сессия не создаётся |
| Восстановить резерв SQLite, сверить количество записей и связи, затем проверить откат | Подтверждена работоспособность выбранного формата и совместимой версии. [Процедура](deployment.md) |

## Предлагаемый состав пакета и выбор последней встречи

Версия с картотекой расширяет перенос активной игры. В неё входят карточки, отдельные сведения и встречи, история их изменений, выбранное последнее наблюдение и связи внутри кампании. Архивная сессия включается один раз, если на неё ведёт рабочая ссылка из этих записей и её может читать экспортирующий игрок. Копируются доступные название, дата и сюжетный дневник. Личные заметки героев, история числовых действий, предложения событий и журнал доступа остаются вне пакета картотеки. Архив без рабочих ссылок не добавляется автоматически. Это позволяет открыть прошлую встречу и прочитать контекст из дневника.

| Ссылка в пакете | Сохранение и результат импорта |
| --- | --- |
| `linked` | Присутствует ID цели в разделе подходящего типа. После импорта выбирается новый ID из карты этого типа. Один архив, на который ссылаются несколько встреч, импортируется один раз |
| `snapshot` | Есть ранее сохранённый видимый текст и, при наличии, исходное происхождение. При чтении отображается «Источник недоступен». Такой ID не преобразуется в ссылку, даже если в новой кампании совпало имя или номер |
| `unknown` | Идентификатор и текст цели отсутствуют. Место и сессия могут быть неизвестны независимо |

Ссылка `linked` без цели нужного типа, повторяющиеся исходные ID внутри одного типа, ссылка на другую кампанию и последнее наблюдение другого лица отклоняют пакет до записи. При экспорте отсутствующей или недоступной цели допустим только уже сохранённый видимый текст. Заголовок, дата и дневник недоступной сессии из БД не извлекаются. Сессия, полученная как архивная цель, открывается через просмотр с проверкой прав. Импорт сохраняет активный контекст новой игры, исходный номер сессии остаётся сведением о происхождении.

Последнее наблюдение — один `latestEncounterId` у лица, допускающий `null`. Запись встречи и установка последней могут идти одной командой с явным выбором. В интерфейсе добавления текущей встречи выбор показывается до сохранения. При добавлении старой либо неуточнённой встречи исходная отметка сохраняется, пока игрок явно её не поменяет. Когда нет выбранной встречи, карточка показывает историю и предлагает выбрать последнюю. Исправление текста меняет сведения этой встречи, сохраняя её ID и прежнюю версию. Сравнение дат может дать подсказку, решение остаётся у игрока.

Проверить совместно: две встречи ссылаются на один архив, новая запись о прошлой игре сохраняет прежнюю отметку, а явное изменение с той же устаревшей ревизией возвращает конфликт. Точный повтор уже принятой команды не меняет последнюю встречу второй раз. После переноса рабочая ссылка открывает импортированную сессию. Текст недоступного источника читается, даже если импорт не включал архив. Точную версию и лимиты пакета выбирают при реализации вместе с миграцией и совместимым откатом.

## Проверка отзыва прав на действующих командах

В SQLite RAM ведущий записал место и задание, переключился в другую доступную кампанию и точно повторил обе команды. Квитанции указали исходную кампанию, текущий выбор сохранился. После понижения в исходной кампании до игрока повтор вернул 403. После удаления из исходной кампании повтор и чтение её архивной сессии вернули 404. Осталось по одной исходной записи, без повторных изменений. [Проверка](../tests/access.test.mjs)

Контракт и состав пакета передаются геймдизайнеру и QA. API, чтение старых данных после миграции и репетиция отката проверяются при реализации #87. UI #88 использует согласованную схему.

## Первый серверный срез · 24.11.2026

Модель и HTTP проверяются через `openStore(filename, {campaignPeople:true})`. В штатном запуске картотека выключена по умолчанию. `SKAZ_CAMPAIGN_PEOPLE=1` требует индивидуального HTTPS-входа и формата профиля v15. В SQLite ключ карточки включает кампанию, история привязана к той же паре и команде. Снимки «было/стало» и квитанция фиксируются одной транзакцией.

| Запрос | Ответ или данные команды |
| --- | --- |
| `GET /api/campaign-people` | Ревизия, контекст, компактные карточки и последнее наблюдение. У карточки есть `latestPlaceTitle`, когда место последней встречи разрешается в текущей кампании |
| `GET /api/campaign-people/:id` | Ревизия, контекст, данные лица, сведения, встречи, связи и `latestEncounterId` |
| `GET /api/campaign-people/:id/history?beforePosition=N` | До 10 снимков, от позднего к раннему, `nextBeforePosition` для следующей страницы. Параметр необязательный, граница исключающая |
| `POST /api/campaign-people` | `{mutationId,expectedRevision,campaignId,personId,operation,data}`. Действуют существующие Origin и `X-Skaz-Client` |

Команды и поля `data`:

- `create` принимает `{details:{name,description,relation},knowledge}`. Первое сведение можно сохранить в той же транзакции или передать `knowledge:null`. `edit` принимает только `{name,description,relation}`.
- `add-knowledge` принимает `{id,kind,text,sessionId}`. `edit-knowledge` меняет текст и сессию, а `confirm-knowledge` с `{id}` отдельно меняет вид предположения.
- `add-encounter` принимает `{id,text,sessionId,placeId,makeLatest}`. `edit-encounter` обновляет те же значения без `makeLatest`. `choose-latest` принимает `{id}` известной встречи этого персонажа или `{id:null}`.
- `set-links` принимает `{links:[{kind,id}]}`. Поддержаны `person, place, quest, session`. Снимки недоступных целей сохраняются. `remove-link-snapshot` удаляет выбранный снимок по `{index}` в текущей ревизии.

Команды используют действующий лимит JSON-запроса 512 КиБ. До 1000 лиц на кампанию, 128 записей каждого из двух видов в карточке, 64 прямые ссылки. Имя до 120 символов, тексты до 1200. Неуказанные сессия и место остаются раздельными `null`.

Проверка `node --test tests/campaign-people.test.mjs` охватывает SQLite RAM, HTTP общего и индивидуального режимов и синтетическую базу на диске. Отказ записи истории откатывает карточку и ревизию. Резерв открывается с прежней карточкой, историей и работающим точным повтором. При выключенном режиме база сохраняет данные, JSON-экспорт v1–v15 даёт 409 для кампании с картотекой. Полная SQLite-копия сохраняет картотеку. Защищённый API [выпущен в `2410183`](https://github.com/garrimajo5/skaz/issues/87#issuecomment-7128279711). [Интерфейс #88](design/campaign-88-acceptance.md) выпущен в `4f092b8`.

## Пакет картотеки v1

`GET /api/export/campaign-memory` отдаёт JSON `skaz-campaign-memory` v1 с игрой v15. `POST /api/import/campaign-memory` принимает `{mutationId,expectedRevision,destination:'new-campaign',file}` с прежней проверкой Origin и заголовка приложения. Старые JSON-маршруты возвращают 409, если выгрузка потеряла бы картотеку. Для кампании, которой одновременно нужен перенос личных изображений, используется полная SQLite-копия.

В пакете `game.source.context` задаёт область рабочих ссылок. В `memory` передаются карточки, история, архивы и массивы исходных ID мест и квестов в порядке записей v15. Рабочая ссылка содержит `status:'linked'`, `campaignId` и `id`. Снимок содержит `status:'snapshot'`, видимый `text` и `origin: {campaignId,id} | null`. Неизвестная цель представлена `{status:'unknown'}`. Место и сессия независимы. Один архив на несколько ссылок копируется один раз. Его исходный номер, дата и название читаются через адрес архивной сессии. Архивный дневник включает записи типов «Событие сессии» и «Зацепка».

Рабочие ссылки при импорте получают новые ID. Снимки представлены `sessionId:null` с `sessionSnapshot`, `placeId:null` с `placeSnapshot` или `{kind,id:null,snapshot}` в связях. Правка текста их сохраняет. Для явного удаления снимка команда `edit-knowledge` или `edit-encounter` передаёт `clearSnapshots` со значениями `'session'` или `'place'` и `null` в соответствующем поле. Рабочая цель заменяет снимок. История возвращает `position` для пагинации и `origin` с исходными ID и ревизией. Импортированные записи сохраняют происхождение без создания старых квитанций в новой игре.

Предел файла 8 МиБ и 4096 изменений на пакет. При превышении нужен полный SQLite-резерв. [Правило Nginx](../deploy/nginx-campaign-memory.conf.example) увеличивает лимит только на точном маршруте импорта. Перед активацией проверить отдельное восстановление, прежние лимиты, оба входа, импорт синтетического файла больше 512 КиБ и точный повтор. Для совместимого возврата отключить `SKAZ_CAMPAIGN_PEOPLE` на том же runtime и оставить текущую SQLite. Прежний код до #87 не поддерживает сохранённую картотеку при экспорте. На восстановленной копии проверить повторное включение, историю и чтение перенесённого архива. [Правила выпуска](deployment.md)
