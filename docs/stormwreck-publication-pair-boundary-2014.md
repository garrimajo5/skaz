# Stormwreck: два источника и частичное повторное использование

21.11.2026, #77 D05. [Отчёт](../catalog/stormwreck-publication-pair-boundary-2014.json) разделяет Dragons of Stormwreck Isle/provider94 и Intro to Stormwreck Isle/provider128. [Статья издателя](https://www.dndbeyond.com/posts/1582-intro-to-stormwreck-isle-your-free-introduction-to) называет два вводных столкновения. Только Drowned Sailors прямо отнесено к первой главе основной книги; происхождение Voyage относительно полного приключения этим не установлено. [Основное оглавление](https://www.dndbeyond.com/sources/dnd/dosi) подтверждает локатор Drowned Sailors.

Это reference-связь, а не доказательство равенства текста столкновений, всего Intro или всей первой главы. Общее обозначение Starter Set не создаёт алиас другой книги или исторический sourceId. У обеих записей собственные numeric/canonical ID остаются неизвестными; полные правила и права не приняты.

## Ограничение захвата

Анонимный запрос Intro оборвался при чтении через25секунд. Два других тела сохранились, но пакетный сборщик потерял их HTTP-квитанции. Поэтому отчёт закрепляет только известный requestedURL, байты, SHA и canonical/h1 внутри тела. httpStatus/finalUrl=null; они не восстановлены предположением. Доступ к Intro и статус его промо не проверены. Повторных сетевых попыток и входа не было.

## Проверки

8Python и реальная репродукция двух сохранённых тел прошли: два encounter-reference, одно явное reuse, точный fragment, отдельные94/128 и запрет выдумать потерянные HTTP-метаданные. Скрипт: `python scripts/audit-stormwreck-publication-pair-2014.py <capture-folder>`. HTML и проза внеGit. Независимое read-only ревью отдельно; это свидетельство с более слабым transfer-provenance, чем полные receipt-captures.

Чтобы этот сбой не повторялся, добавлена [утилита захвата](publication-witness-capture.md). Она не усиливает задним числом текущие артефакты. Далее — обновить текущий триаж после независимого ревью, сохранив ограничения версий/полных записей/прав. Runtime, VPS, профили и этапы не менялись.

Рефлексия content: потеря квитанции соседа — ошибка процесса захвата. Предложение planner: фиксировать started/headers/final отдельно для каждого ресурса и проверять частичные сбои. Польза — сохранность происхождения; цена — небольшой sidecar; риск недоступного полного текста остаётся явным.
