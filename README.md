# СКАЗ

Интерактивный лист персонажа и дневник приключения для **D&D 5e 2014**. Основной сценарий — игрок с планшетом на очной сессии с интернетом.

## Текущее состояние

Локальное клиент-серверное приложение **0.2**. Node.js обслуживает интерфейс и API, SQLite хранит прогресс. **Полярис** — основная тема. Уголь и Атлас сохранены; выбор темы запоминается отдельно в каждом браузере.

Работают лист персонажа, поиск восьми демо-заклинаний, расход ячеек, здоровье, вдохновение, отдых, журнал, подтверждение событий, задания и заметки на схематической карте. Можно изменить имя персонажа, краткое описание, название кампании и максимум хитов. Начальные данные вымышлены; изменения сохраняются в базе между запусками.

Есть статус сохранения, защита от конфликтов вкладок и повторных запросов, локальные черновики при сбое, история сохранений, экспорт/импорт прогресса и резервные копии SQLite. Полный каталог, создание произвольных классов, несколько персонажей, авторизация и распознавание речи ещё не реализованы. Механики примера рассчитаны на барда 5 уровня. Ссылки на dnd.su не являются интеграцией.

Кампания, персонаж и сессия хранятся в связанных таблицах с постоянными ID. Существующая игра переносится автоматически. Кнопка «Кампании» открывает список, переключение и создание из демо-шаблона барда 5 уровня. Прогресс хранится раздельно; сюжет, задания и карта пока демонстрационные. Перед обновлением останови предыдущий сервер и сделай резервную копию старой версией. [Совместимость, API и перенос базы](docs/entities.md).

## Запуск

Нужен Node.js 24 или новее. Внешних пакетов нет, установка зависимостей не требуется.

```sh
npm run dev
```

Открой http://127.0.0.1:4173. При первом запуске автоматически создаётся `data/skaz.sqlite`. Приложение пока доступно только с этого компьютера; для подключения планшета по сети нужен следующий этап настройки доступа.

Если Node установлен без npm, запуск: `node scripts/dev.mjs`, сборка: `node scripts/build.mjs`, тесты: `node --test --test-isolation=none tests/*.test.mjs`.

```sh
npm run check
npm test
npm run build
npm run backup
```

Сборка создаёт клиент в `dist/` и автономный `dist/skaz.html`. HTML-файл при открытии без сервера остаётся демонстрацией с браузерным сохранением; для настоящей базы используй HTTP-адрес локального приложения. Шрифты загружаются из Google Fonts; при недоступности используются системные.

## Резервные копии и перенос

«Данные и настройки → Скачать прогресс» экспортирует JSON. Там же можно восстановить прогресс из файла; перед заменой интерфейс предлагает скачать текущий. `node scripts/backup.mjs` создаёт полную копию базы с историей в `backups/`, даже когда приложение работает. Для восстановления SQLite останови сервер и запусти его с `SKAZ_DB`, указывающим на копию; не заменяй файл работающей базы. Копии стоит хранить и на другом диске.

`data/`, `backups/` и SQLite-файлы исключены из Git. По умолчанию проверяется не более 512 КиБ на сохранение. Лимиты первой версии: 2000 записей журнала, 2000 личных заметок и 1000 заметок карты; общий лимит размера может наступить раньше.

## Структура

- `client/` — интерфейс, темы и транспорт сохранений.
- `server/` — HTTP API, валидация, SQLite и история изменений.
- `tests/` — проверки сохранения, конфликтов, повторных запросов, резервных копий и HTTP API.
- `docs/local-api.md` — контракт API и границы текущего хранения.
- `docs/hosting.md` — требования к будущему хостингу и распознаванию.
- `docs/product-concept.md` — продуктовый концепт, архитектура и этапы MVP.
- `docs/design/` — концепт-арт и правила темизации.
- `scripts/` — локальный запуск и сборка без зависимостей.

## Следующие этапы

Сервер также поддерживает [начало следующей сессии и архив журнала](docs/sessions.md), сохраняя текущие ресурсы персонажа. Кнопка «Сессии» открывает список, начало следующей сессии и архив для чтения. Название и дата текущей сессии показываются в заголовке; вымышленные записи исключены из журнала и экспорта.

Очередь и проверки: [план разработки](docs/DEVELOPMENT_PLAN.md). Серверный [каталог](docs/catalog.md) подключён к «Справочнику»: поиск RU/EN, категории, страницы и сведения об источнике. Поддерживается личный JSON-импорт. «Магия» пока использует отдельные демо-заклинания. Стартовый пакет ссылок: `node scripts/import-catalog.mjs catalog/references.json --apply`.

1. Доработать UX Поляриса на реальном планшете, сохраняя совместимость тем.
2. Развить локальный агрегат прогресса в отдельные сущности персонажей, кампаний и сессий; добавить создание персонажа и вход пользователей.
3. Подключить каталог 2014 с указанием источника и версии каждого материала.
4. Проверить извлечение сюжетных событий на короткой записи, затем на полной сессии.

Перед массовым импортом материалов нужно определить доступный способ подключения и условия использования источника. Секреты и аудиозаписи в репозиторий не добавляются.

Каталог: доступна небольшая проверенная подборка четырёх состояний, двух заклинаний, пяти магических предметов, двух существ и одного артефакта SRD 5.1 (CC BY 4.0) с русским кратким изложением, структурой основных полей и атрибуцией. Это не полная база; загрузка и охват описаны в [документации каталога](docs/catalog.md).

Серверный инвентарь: добавление предметов/артефактов из каталога, количество и отдельное хранение у персонажа с защитой повторов. В карточках предметов/артефактов справочника есть добавление с количеством; «Герой → Инвентарь → Открыть» показывает сохранённые предметы. В инвентаре работают списание количества и отмена последней операции до следующего изменения игры. Применение эффектов предметов пока не подключено. Инвентарь сохраняется в SQLite backup; JSON переноса прогресса v1 пока его не включает. [Контракт и ограничения](docs/local-api.md#инвентарь-серверный-этап).

Сервер также умеет экспортировать активную игру с инвентарём и источниками через `GET /api/export/active` (JSON v2). Серверный импорт `POST /api/import/active` переносит этот файл в новую кампанию с инвентарём, проверяя источники и конфликты. В настройках доступны скачивание v2 и импорт с предпросмотром в новую кампанию; HTTP-лимит — 512 КиБ.

На сервере появился отдельный список заклинаний персонажа из каталога (`/api/spellbook`): ручные отметки изучено/подготовлено и удаление. В разделе «Магия» кнопка «Мои заклинания из каталога» открывает сохранённый список; карточка справочника позволяет добавить запись. Можно читать и менять ручные отметки или убрать запись. Серверный экспорт `/api/export/active-v3` и импорт v3 переносят список; настройки экспортируют v3 и принимают v1/v2/v3. Полный SQLite backup также его сохраняет.
